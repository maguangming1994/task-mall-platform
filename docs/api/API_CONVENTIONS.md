# API 通用约定

## 1. 基础规范

- API 前缀：`/api/v1`。
- 数据格式：UTF-8 JSON。
- 字段命名：`snake_case`。
- 时间：ISO 8601，例如 `2026-08-03T08:00:00Z`。
- 现金金额：人民币分整数。
- 积分：整数。
- 对外资源使用 ULID，不暴露数据库自增主键。

## 2. 客户端请求头

```http
Authorization: Bearer <token>
X-Client-Platform: wechat-mini | h5-wechat | h5-browser | admin-web
X-App-Version: 1.0.0
X-Device-Id: device-public-id
X-Request-Id: optional-client-request-id
Idempotency-Key: required-for-critical-writes
```

服务端始终返回 `X-Request-Id`，用于日志和客服排查。

## 3. 响应格式

成功：

```json
{
  "code": "OK",
  "message": "success",
  "data": {},
  "request_id": "01J..."
}
```

失败：

```json
{
  "code": "ORDER_STOCK_INSUFFICIENT",
  "message": "部分商品库存不足",
  "details": {
    "sku_id": "01J..."
  },
  "request_id": "01J..."
}
```

HTTP 状态码表达协议级结果，业务 `code` 提供稳定判断依据。客户端不能依赖可变的中文 `message` 判断逻辑。

## 4. 分页

MVP 支持：

```text
page=1&page_size=20
```

响应包含：

```json
{
  "items": [],
  "pagination": {
    "page": 1,
    "page_size": 20,
    "total": 0,
    "last_page": 1
  }
}
```

订单列表 `GET /api/v1/orders` 已按此约定分页：支持 `page`、`page_size`（默认 20，最大 100）和 `status` 过滤，响应包含 `last_page`，客户端需逐页拉取或滚动加载，禁止假设一次返回全部订单。

数据量较大的积分流水、社区内容和订单后续切换为 `created_at + id` 游标分页。

## 5. 幂等

下列请求必须携带 `Idempotency-Key`：

- 领取任务、提交成果和审核
- 签到及奖励事件
- 创建订单、取消订单
- 创建支付、退款和人工补偿
- 创建提现和后台用户资产调整
- 发放、扣除或撤销积分
- 锁定、使用和返还优惠券

同一用户、同一路径、同一幂等键和相同请求体返回首次处理结果。相同键但请求体不同返回冲突错误。

## 6. 认证和授权

- 用户端 Access Token 默认 2 小时，可轮换 Refresh Token 默认 30 天；后台配置变更默认只影响新签发会话。
- 微信小程序、公众号身份和手机号最终绑定到统一用户。
- 微信外 H5 不依赖公众号网页授权。
- 管理后台使用独立客户端和更严格的登录、会话及审计策略。
- 同一用户默认最多保留 5 台活跃设备；退出、设备移除、账号禁用和注销会撤销对应 Refresh Token 会话。
- 服务端对资源归属和角色权限进行校验，不能只依赖前端隐藏按钮。

## 6.1 任务提交与奖励

- 首版任务只允许后台账号的平台管理员创建和发布；管理后台和用户端任务发布中心调用同一任务领域服务。
- 普通用户和机构发布阶段由 `/client-capabilities` 返回，首发必须为 `closed` 且 `external_task_publishing_enabled=false`；客户端不能仅凭本地开关展示申请入口。
- `user/organization` 发布主体和 `partner_portal` 仅作为未来兼容枚举，当前普通用户 Token 调用发布接口仍返回无权限；外部发布不得复用后台 RBAC 或平台管理员会话。
- 用户端发布接口要求独立 `publisher` Token，其受众、权限范围和时效与普通用户 Token 隔离；所有写操作同时校验后台账号、发布主体和 `task.frontend_publish` 权限。
- 发布接口默认只能读写当前发布主体自己的任务；超级管理员跨发布主体管理使用 `/admin/tasks`，不能通过客户端传入发布者 ID 绕过范围限制。
- 草稿预览不可公开检索；提交发布时重新校验完整规则并创建发布申请，命中高风险条件时进入审批，发布者不得自审。
- 主动领取使用事务内条件更新占用名额，幂等重试不能重复增加领取数；系统自动加入以 `task_id + user_id + cycle_key` 幂等创建用户任务。
- 领取事务同时更新历史领取数、当前占位数和全部奖励预留；只有全部成功才提交。名额判断使用“当前占位 + 成功奖励 < 最大成功奖励次数”，不能使用历史领取数。
- 服务端生成周期标识和实际完成期限；实际期限取领取后配置窗口与任务全局截止时间中的较早值。
- 取消、未完成过期和最终驳回通过同一幂等释放服务减少当前占位并释放奖励；取消记录保留，因此当前周期不能重新领取。
- 任务大厅列表和详情允许游客访问，也可携带用户 Token 返回资格与用户任务状态；定向保密任务在资格过滤后仍不可见时统一按资源不存在处理。
- 推荐排序由服务端配置生成。用户端发布者只能提交推荐位申请，不能在任务写接口中设置置顶、顺序或有效期。
- 列表剩余名额和资格只代表响应时快照，领取接口必须重新校验。
- 已发布任务修改生成不可变版本，由服务端字段差异判定普通或重大变更；重大变更重新校验预算、风险和审批。
- 新版本只影响发布切换后的新领取。已有用户任务继续使用领取快照，不得通过更新接口批量迁移。
- 有进行中用户的关闭请求必须提交处理策略并转后台审批；已关闭任务不能恢复，只能克隆为新草稿。
- 回滚复制历史版本形成新版本，不直接把当前版本号指向历史记录。
- `claim_and_submit` 才能调用成果提交接口；`claim_and_auto_verify` 和 `auto_enroll` 只由可信服务端业务事件推进完成，客户端上报不能作为达标依据。
- 每次提交生成不可变提交序号；撤回只改变状态，不删除记录或返还提交次数。
- 审核开始接口锁定提交，之后用户不能撤回；驳回原因必须保存并向用户展示。
- 申诉关联原提交和原审核人，服务端强制申诉审核人与原审核人不同。
- 审核通过与奖励发放解耦。积分、优惠券、余额各自使用 `task_claim_id + reward_type + sequence` 幂等键并独立重试。
- 单用户余额奖励超过 200 元时，发布或修改任务先进入财务二次审核，不能通过普通任务接口绕过。

## 6.1.1 任务奖励预算

- 客户端为每个奖励组件提交平台预算池、活动总奖励次数和周期上限；服务端根据奖励快照计算所需积分、券数量或余额分值。
- 提交发布时在一个事务中锁定全部奖励预算；任一组件不足返回 `TASK_BUDGET_INSUFFICIENT`，不得部分发布。
- 领取或系统自动加入时，在创建用户任务的同一事务中预留全部奖励组件；任一预留失败不创建用户任务或占用名额。
- 发布者不能通过请求体提交发布主体、个人资产账户、预算汇总值或已发放值。
- 预算追加和减少使用版本号、幂等键及审计原因；减少后不得低于已预留加已发放值。
- 奖励失败保持预算预留。只有发放成功、按规则释放或实际追回后才能推进预算状态。

## 6.1.2 任务内容与风险案件

- 任务发布、重大修改、成果提交和用户举报统一进入任务风控服务；风险等级、命中规则和处置动作以不可删除记录保存。
- 低风险可按规则直接通过，中风险进入人工复核，高风险可先隐藏任务、停止领取或冻结奖励，再由人工给出最终结论。
- 外部链接只能使用后台已发布的域名允许名单；客户端不得把链接是否安全作为最终依据。
- 任务成果自动核验只接受可信服务端业务事件。附件上传完成后必须经过隔离、类型一致性、病毒和内容扫描，扫描通过前不可用于审核或公开访问。
- 举报数量只提高排查优先级，不能单独构成违规结论；同一用户对同一任务的重复有效举报必须幂等拦截。
- 去重与多账号识别可以组合手机号、设备、IP、支付身份和行为信号，但不得只凭单一信号执行永久处罚。
- 风险接口只向有权限角色返回必要结论和脱敏证据，不返回原始凭证、完整设备标识或其他无关个人信息。
- 发布者风险申诉必须由与原处理人不同的审核人复核；误判恢复、补偿和权限变更均记录审计链。

## 6.2 积分欠额

- 可用积分、冻结积分和欠额分别使用非负整数字段，禁止通过负余额表达欠额。
- 撤销奖励时先冲减原批次剩余值，不足部分创建欠额及 `debt_create` 流水。
- 所有正向积分入账先记录来源，再按最早欠额分配 `debt_repay` 流水；仅剩余部分创建可用批次。
- 欠额大于零时积分消费、冻结和积分订单返回 `POINT_DEBT_OUTSTANDING`。
- 欠额减免必须幂等并记录原因，超过 1000 积分返回待二次审核状态，不能先执行后审批。

## 6.3 客户端能力与支付场景

- 用户端启动、登录状态变化和进入结算前读取 `/client-capabilities`，合并本地运行能力与服务端已发布权限。
- 结算预览、创建订单和微信支付提交 `X-Client-Platform` 及能力版本；版本过期返回 `CLIENT_CAPABILITY_STALE`，客户端刷新后重新预结算。
- `wechat-mini` 只创建小程序支付，`h5-wechat` 只创建 JSAPI 支付，`h5-browser` 仅在 H5 支付已开通时创建 MWEB 支付。
- 当前场景不可支付时，在库存预占前返回 `PAYMENT_SCENE_UNAVAILABLE`；余额足额支付仍按照钱包规则独立判断。
- 分享参数只接受公开目标 ID 和签名推荐码，禁止把 Token、手机号、OpenID 等写入链接。

## 6.4 协议、同意与隐私请求

- 公共协议接口返回当前生效版本；历史版本只在明确请求时返回，内容摘要用于校验展示内容未被替换。
- 用户接受或撤回协议只追加新记录，不覆盖原同意时间；必要协议撤回前必须展示对服务范围的影响。
- 查询、复制、更正、删除和撤回可选授权使用隐私请求状态机；账号注销继续使用独立的冷静期和资产检查接口。
- 数据副本使用私有、短期签名下载地址，不在普通日志记录地址或导出内容。
- 删除请求必须返回可理解的阻断类别，并在法定留存或法律冻结期间限制数据的其他用途。

## 7. 创建订单

客户端只提交 SKU、数量、购买方式，以及各交付分组的优惠券、地址和现金支付方式。服务端必须重新计算：

- 商品是否可售
- 购买方式是否启用
- 现金与积分价格
- 库存和限购
- 优惠券可用性及分摊
- 现金运费
- 最终现金与积分应付
- 用户余额可用金额及需要外部支付的剩余现金

同一次结算按 SKU 的交付类型拆成一个或多个订单，并返回统一结算批次。每个交付分组分别提交地址、优惠券和现金支付方式；实体物流必须有地址，一个拆分订单最多使用一张优惠券。每个订单独立保存价格、限购、预占、履约和自动完成规则快照。

创建待支付订单后默认预占库存 15 分钟。订单超时关闭、支付成功和用户主动取消必须通过同一幂等状态机消费或释放库存预占、冻结积分和锁定优惠券。

实体物流运费由服务端按订单地址、模板版本、计费件数或重量、偏远附加费和包邮规则计算。相同模板合并计费，不同模板分别计算后相加；客户端金额不作为入账依据。订单保存运费计算快照。

同一订单允许分批履约，每批提交订单项及数量、承运商和物流单号。服务端校验累计履约数量，物流轨迹查询失败不能回滚已确认的发货动作。

前端展示的预结算结果不能作为最终入账依据。

余额属于现金应付部分的资金来源。客户端提交余额或微信支付方式，两者互斥。选择余额时必须足额覆盖包含运费在内的全部现金应付，余额不足返回业务冲突，并在创建订单事务中完成冻结与扣除；选择微信时不产生钱包冻结。退款沿用订单唯一现金资金来源，余额订单退余额，微信订单原路退回。

## 8. 钱包与提现

- 钱包余额、冻结、消费、退款、提现和人工调整必须具有不可删除流水。
- 提现申请先冻结余额，渠道成功后扣除，失败或拒绝后解冻。
- 后台清零使用反向调整流水，不能直接覆盖账户余额。
- 提现渠道通过适配器接入，业务接口不暴露渠道私有字段。
- 余额、提现和人工调整接口均要求幂等键。

## 9. 并发版本

后台编辑任务、商品和规则时提交 `version`。版本不一致返回 `409 RESOURCE_VERSION_CONFLICT`，要求刷新后重新编辑。

## 10. 支付回调

- 支付渠道回调使用独立公开路由，不使用用户 Bearer Token。
- 必须验签并校验商户、应用、订单、金额和币种。
- 原始回调敏感数据不得直接写普通日志。
- 服务端以第三方交易号和通知 ID 去重。

## 11. 版本和废弃

- 非兼容变更进入新的 API 主版本。
- 新增可选字段属于兼容变更。
- 删除或改变字段语义前提供废弃期和迁移说明。
- OpenAPI 文件是前后端接口的唯一契约来源。

## 12. 后台配置

- 默认参数通过类型化配置接口读写，客户端不能提交任意未定义配置键。
- 保存草稿与发布配置分开，草稿不影响线上业务。
- 发布请求携带当前版本，高风险配置还需要审批记录。
- 发布只影响新业务，已领取任务、积分批次、订单、优惠券和售后使用业务快照。
- 配置发布后由服务端发送缓存刷新事件。

错误码见 [`ERROR_CODES.md`](ERROR_CODES.md)，初始契约见 [`../../packages/api-contracts/openapi.yaml`](../../packages/api-contracts/openapi.yaml)。
