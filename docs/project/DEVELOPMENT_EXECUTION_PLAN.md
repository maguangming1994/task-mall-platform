# 开发执行计划

## 1. 迭代方式

- 默认两周一个迭代，设计至少领先开发一个迭代。
- 使用相对迭代编号，不在团队配置、启动日和外部资质未知时承诺具体发布日期。
- 每个迭代只承诺可演示、可测试的纵向业务结果，不以“完成若干文件”作为业务完成。
- P0 阻断、账务差异、安全问题和生产资质优先级高于新功能。

## 2. 推荐实施顺序

| 迭代 | 目标结果 | 主要内容 |
|---|---|---|
| I0 基线与环境（已完成） | 新环境一次启动、CI通过 | 版本锁定、uni-app/React/Laravel、PostgreSQL、Redis、MinIO、健康检查、CI与锁文件 |
| I1 认证与治理（本地完成） | 用户和后台安全登录 | 微信/手机号、统一身份、会话设备、RBAC、审计、配置中心、上传、协议同意 |
| I2 任务资产基础（本地完成） | 可发布并参与基础任务 | 任务/版本/预算、领取名额、提交审核、积分批次、优惠券、钱包流水 |
| I3 任务完整闭环（本地完成） | 任务大厅到奖励可验收 | 三种参与方式、自动核验、申诉风控、推荐位、通知、前端发布中心 |
| I4 商城与库存（本地完成） | 可配置商品并创建订单 | 分类、SPU/SKU、三种购买方式、库存、购物车、地址、运费、结算预览 |
| I5 支付与订单（本地完成） | 两种现金来源可完成支付 | 余额全额、微信各场景、订单状态、回调、超时关闭、对账基础 |
| I6 履约与售后（本地完成） | 交付、退款、退换货闭环 | 物流/无需物流/虚拟、分批履约、部分退款、退货、换货、运费补偿 |
| I7 社区与运营（本地完成） | 社区成长和后台运营可用 | 帖子评论、奖励、举报申诉、消息、后台页面、隐私请求、基础看板 |
| I8 硬化与发布（本地完成，生产待授权） | 达到灰度门槛 | 全矩阵回归、并发/安全/性能、真机、恢复/回滚、生产资质、UAT和灰度 |

实际拆分可根据团队并行能力调整，但依赖顺序、P0 结果和质量门槛不变。

## 3. 团队职责（姓名待填）

| 职责 | 负责人 | 必须承担的结果 |
|---|---|---|
| 产品/需求 | 待提供 | 基线、验收、变更、范围和业务决策 |
| UI/UX | 待提供 | 原型、Token、组件、图标、交付与设计走查 |
| uni-app 前端 | 待提供 | 小程序/H5实现、多端适配、契约联调 |
| 管理后台 | 待提供 | 后台页面、权限呈现、配置与审核体验 |
| PHP 服务端 | 待提供 | 领域逻辑、数据、接口、队列、外部适配与审计 |
| 测试 | 待提供 | 追踪矩阵、自动化、真机、回归和发布质量结论 |
| 运维/安全 | 待提供 | 环境、CI/CD、监控、备份、恢复、安全和事故响应 |
| 运营/客服/财务 | 待提供 | 内容、SLA、支付/资产对账、UAT和上线值守 |

一人可以承担多个职责，但审批、财务和高风险复核仍须满足异人原则。

## 4. 开发就绪 DoR

进入开发前必须具备：确认的需求/非目标、已评审原型与页面状态、OpenAPI 与数据权限、数据库变化、正常/异常/权限/并发验收场景、测试数据、依赖与功能开关、负责人和验收人。

缺少支付资质、品牌素材或生产账号时，可以开发适配器和测试路径，但不得把生产功能标记完成。

## 5. 完成定义 DoD

- 代码、迁移、OpenAPI、业务文档和测试同步更新。
- 格式、静态分析、单元、接口、集成和适用 E2E 通过。
- 正常、异常、权限、并发、幂等和补偿路径通过。
- 日志、指标、审计、告警和人工处理入口能够定位问题。
- 设计走查和目标端真机通过，无 P0/P1 和账务差异。
- 数据迁移、配置、开关、回滚/前向修复和发布说明齐全。

## 6. 每周监督

每周看板至少更新：本周目标、交付状态、阻塞、风险、变更、缺陷、设计、接口/迁移、发布、核心指标和负责人。风险登记表每周复核；新增高风险项必须有缓解动作和完成时间。

## 7. 下一步

第 5 至第 30 批本地开发、全量回归和部署门禁已完成。当前进入产品化验收阶段：V1 视觉系统、首页和核心导航已落地，并提供幂等演示数据。下一项是逐页设计走查、本地业务 UAT、微信双端真机联调和预发布部署；生产微信、支付、短信、正式扫描器与主体资料在取得真实凭据前保持关闭。
