# 商城、履约与售后实施框架 V2

更新时间：2026-08-13

## 1. 本批目标

把商品购买、结算、支付、履约、退款、退货退款和换货收敛成一条由服务端裁决的业务链。移动端和管理后台不再各自推断可操作状态，只消费接口返回的金额、数量、责任和下一步。

## 2. 已确认的核心规则

| 领域 | 统一规则 |
| --- | --- |
| SKU 购买方式 | 同一 SKU 可分别开启现金、积分、现金 + 积分三种方式 |
| 现金支付来源 | 一笔结算中的现金部分只能全额余额或全额微信支付，禁止余额 + 微信组合 |
| 运费 | 只用现金结算，不参与积分支付；退货时原发货运费不退 |
| 优惠券 | 可抵扣现金或积分；累计达到整单全额退款时退回，部分退款默认不退回 |
| 部分退款 | 可按订单项数量多次申请；累计数量、现金和积分均不得超过剩余可退值 |
| 换货 | 仅已交付/已完成订单开放；换货数量与退款占用共同扣减剩余可售后数量 |
| 未发货 | 仅退款，无需用户填写退货物流 |
| 已发货 | 可按服务端下发类型选择仅退款、退货退款或换货 |
| 无需物流/虚拟商品 | 售后 return_method 固定为 `no_logistics`，不得提交物流寄回 |
| 退货责任 | 原因给出默认责任和运费承担方，管理员改变默认判定必须留下审核理由 |
| 退货运费补偿 | 每次必须同时提供物流单号和实际付款凭证；按后台上限核定 |
| 用户操作期限 | 审核后需寄回的售后默认 7 天，后台统一可配置；逾期自动关闭 |
| 积分退款 | 重新生成 `order_refund` 来源积分批次，按退款规则重算有效期 |

## 3. 统一售后工作流对象

订单接口的每个订单项新增 `after_sale_workflow`：

| 字段 | 用途 |
| --- | --- |
| `allowed` | 当前是否显示售后主入口 |
| `available_service_types` | 当前真实可选的仅退款、退货退款、换货集合 |
| `recommended_service_type` | 从订单详情进入时的默认类型 |
| `return_method` | 服务端确定物流寄回或无需物流 |
| `requires_return_logistics` | 表单是否必须进入寄回物流阶段 |
| `has_active_after_sale` | 是否已有退款/换货占用数量 |
| `summary` | 给用户看的中文状态和原因 |

移动端不得再仅凭订单状态自行拼接售后类型；提交前以该对象为准，服务端仍进行最终并发校验。

## 4. 状态与页面映射

| 订单/售后状态 | 用户端主动作 | 管理后台主动作 |
| --- | --- | --- |
| `pending_payment` | 完成整单现金支付 | 查看支付占用与超时 |
| `pending_fulfillment` | 查看订单；可申请仅退款 | 发货/无需物流交付/虚拟交付 |
| `fulfilled` | 确认完成；按工作流申请售后 | 查看物流与售后占用 |
| `completed` | 查看资产和可售后数量 | 查看已完成订单 |
| `partially_refunded` | 查看剩余可退数量 | 继续处理剩余订单项 |
| `submitted` | 等待审核 | 判定责任、运费承担和退回方式 |
| `awaiting_return` / `waiting_return` | 期限内提交物流与付款凭证 | 等待用户寄回 |
| `return_in_transit` | 查看寄回进度 | 仓库验收 |
| `processing` | 等待支付渠道退款 | 处理渠道结果与重试 |
| `replacement_pending` | 等待换货发出 | 发出替换商品或无需物流交付 |
| `succeeded` / `completed` | 查看现金、积分、运费补偿结果 | 查看审计闭环 |
| `closed` | 查看关闭原因 | 查看超时关闭记录 |

## 5. 本轮已落地

- PHP 订单 presenter 统一计算售后工作流。
- uni-app 订单详情展示服务端售后说明和真实入口。
- uni-app 售后申请直接读取单个订单详情，不再下载全部订单后本地查找。
- 售后类型、默认类型和退回方式全部使用服务端结果。
- 管理后台订单详情展示退款占用、换货占用与剩余可售后数量。
- 自动化测试覆盖未发货仅退款、物流订单三类售后、剩余数量占用、现金/积分累计上限和优惠券返还。

## 6. 后续批次

1. 将售后工作流同步到订单列表摘要，减少进入详情后才发现不可申请的情况。
2. 为管理后台订单项增加“退款占用 / 换货占用 / 剩余可售后”列及并发刷新。
3. 增加物流轨迹提供商适配、渠道退款回调监控与异常重试面板。
4. 增加售后时效、责任归属和运费补偿的运营统计。
