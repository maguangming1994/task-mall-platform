# 任务系统六批 UI 与开发交付说明

更新日期：2026-08-13

## 1. 本轮范围

本轮把模板、批次数据、周期成长、审核工作台、质量风控和用户任务状态作为同一条任务履约链设计，不包含校园跑腿、代取或线下配送等独立履约业务。

## 2. 页面与核心任务

| 端 | 页面 | 用户主任务 | 主操作 | 关键状态 |
|---|---|---|---|---|
| 管理端 | 任务模板中心 | 复用成熟任务结构 | 使用模板创建草稿 | 启用、停用、版本已发布 |
| 管理端 | 批次导入 | 上传并映射任务数据 | 开始预检 | 待映射、预检失败、可导入 |
| 管理端 | 批次预检 | 修复错误并确认分配规则 | 确认导入并发布 | 重复、字段缺失、部分通过 |
| 审核端 | 逐步骤审核 | 核验单个步骤的材料 | 通过/驳回本步骤 | 待审、占用中、需补交、已通过 |
| 用户端 | 周期成长任务 | 查看当前周期目标 | 继续完成任务 | 未开始、进行中、已达成、已结算、已重置 |
| 用户端 | 提交质量与进度 | 理解预检和人工审核进度 | 补充说明/查看记录 | 执行状态与审核状态并列 |
| 管理端 | 质量看板 | 查看规则命中和人工复核结果 | 进入复核 | 提醒、拦截、误判恢复、已关闭 |

## 3. 双状态呈现规则

用户端不得再使用一个模糊状态同时表示“任务做到了哪一步”和“平台审核到哪一步”。统一拆成：

- 执行状态：待执行、执行中、已提交、待补交、已结束。
- 审核状态：未提交、等待审核、审核占用中、部分通过、审核通过、审核驳回、申诉中、申诉复核中。
- 奖励状态：未预留、已预留、待发放、发放中、已到账、发放失败重试中。

列表页显示执行状态为主标签，审核状态为辅助标签；详情页并列显示两种状态，奖励状态放在资产区域。

## 4. 组件与交互规格

### 4.1 批次导入

- 支持 CSV 与 XLSX。
- 上传后先展示文件名、大小、行数和字段数，再进入字段映射。
- 字段映射保存为草稿，预检不会写入正式数据。
- 预检结果分为通过、重复、字段缺失和格式错误；错误行允许导出。
- 确认导入是唯一主操作，需要再次确认数据项数量和分配策略。
- 已发布批次不可覆盖修改；新增数据使用新批次。

### 4.2 逐步骤审核

- 顶部显示审核占用人和剩余占用时间。
- 每次只聚焦一个步骤，材料、OCR 结果、重复相似度和历史审核记录放在同一上下文。
- 驳回必须选择常用原因或填写说明，并明确是只补交当前步骤还是整单重新提交。
- 审核占用超时自动释放；转派保留操作审计。
- 系统预检是辅助信号，不能凭单一信号产生永久处罚。

### 4.3 周期成长

- 每日、每周、每月和里程碑用同一任务卡结构展示。
- 明确显示本周期起止时间、下一次重置时间和奖励结算状态。
- 已达成但奖励处理中与已到账分开表达。
- 重置只创建新周期实例，不覆盖历史进度。

## 5. 响应式规则

- 移动端主操作固定在底部安全区之上，页面内容预留 88px。
- 表格在窄屏转为字段卡片，不横向压缩关键状态。
- 审核材料图片最小点击区域 44px，可进入原图预览。
- 所有状态不得只靠颜色识别，必须同时有中文文案和图形/标签。
- 尊重 `prefers-reduced-motion`，禁用非必要位移动画。

## 6. 多角色评审结论

### 产品经理

- P0：批次发布前必须明确不可变规则和失败回收策略。
- P0：用户端必须同时展示执行与审核状态，避免把“已提交”误解为“已完成”。

### UX 研究

- P1：驳回文案应指向具体步骤与可执行修复，不使用“材料不合格”这类笼统描述。
- P1：周期任务需展示下一次重置时间，减少用户对进度消失的误解。

### 视觉与无障碍

- P1：保留当前校园蓝、亮黄、青绿和珊瑚色，但控制高饱和色只用于主操作和状态信号。
- P1：状态标签需达到可读对比度；图标、文字和颜色三种信号至少保留两种。

### 前端工程

- P0：状态文案使用统一映射表，不能在页面内散落英文原始值。
- P1：批次预检、审核占用与奖励发放需要 loading、empty、error、retry 状态。

### 商业与运营

- P0：质量评分只能作为审核排序和辅助判断，不得直接结算或永久封禁。
- P1：质量看板需要记录规则版本，便于误判申诉和后续复盘。

## 7. 验收标准

- 同一数据项在并发领取时只分配给一个有效领取记录。
- 取消、过期和最终失败后，数据项按规则回收且有审计记录。
- 发布后的模板版本、任务步骤和批次数据快照不会被后续编辑改变。
- 逐步骤审核能只驳回一个步骤，已通过步骤保持锁定。
- 审核占用、释放、转派和完成均有操作人及时间记录。
- 每日、每周、每月重置可重复执行且不会重复发奖。
- OCR、重复材料和异常账号信号可解释、可复核、可申诉。
- 用户端所有状态为中文，并在列表、详情和消息通知中保持一致。
