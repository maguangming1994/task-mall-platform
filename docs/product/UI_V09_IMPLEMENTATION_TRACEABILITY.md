# 校园风 V09 UI 实施追踪矩阵

更新时间：2026-08-23  
设计基线：`design/ui/全量移动端页面-校园风V09-20260823`（58 张）

## 1. 实施原则

- 设计稿是界面与流程基线，真实数据、权限与状态由 API 返回，不在前端伪造业务结果。
- 同一页面用可复用组件承载加载、空、失败、受限、可操作、处理中和完成状态，不为每张状态图复制页面。
- 游客可以浏览公开首页、任务、商城、社区和协议；领取、下单、发布、评论、资产与个人信息操作必须登录。
- 普通用户与“平台发布管理员”使用独立身份和令牌；发布身份不能复用普通用户登录状态。
- 金额统一以分保存、以元展示；积分与余额分别记账；运费只使用现金；余额支付不可与现金组合。
- 任务领取后保存不可变版本快照；任务奖励、订单支付、退款、余额充值等关键操作必须幂等并保留审计记录。

## 3. 角色入口与权限边界

| 角色 | 默认入口 | 可浏览 | 可写操作 | 禁止事项 |
|---|---|---|---|---|
| 游客 | 首页 | 首页、公开任务、商品、社区、协议 | 发送验证码、登录/注册 | 领取任务、下单、评论、发帖、查看资产 |
| 普通用户 | 首页 | 全部用户端公开内容与个人数据 | 领取/提交任务、下单、售后、社区互动、资产操作 | 任务发布、后台审核、人工资产调整 |
| 平台发布管理员 | 发布身份登录 | 自己发布的任务、预算池、领取与提交汇总 | 创建草稿、预留预算、发布、暂停、恢复、结束 | 复用用户令牌、审核自己的提交、越权查看其他发布者数据 |
| 后台运营/审核/财务/超管 | PC 后台 | 按 RBAC 授权范围 | 审核、配置、资产与订单处理、审计 | 绕过复核、隐藏关键资产流水、无理由高风险修改 |

## 4. 核心状态机验收

### 任务

`草稿 → 待发布审核 → 已发布 → 暂停/结束 → 归档`  
`可领取 → 已领取 → 已提交 → 审核中 → 通过/驳回 → 奖励发放/申诉`

发布后的任务步骤、奖励与规则通过版本快照固化；已领取用户不受后续版本修改影响。

### 订单与支付

`待支付 → 已支付 → 待履约 → 已发货/无需物流 → 已完成`，异常分支为 `已关闭/部分退款/全额退款/换货中`。

支付渠道仅允许以下单选组合：

- 现金；
- 余额（必须全额覆盖，不与现金组合）；
- 积分；
- 现金 + 积分（商城 SKU 开启时）；

运费始终使用现金，不参与积分、余额或优惠券抵扣。

### 余额充值

- 卡密：校验成功后立即入账，卡密一次性使用；
- 在线支付：创建充值单 → 调起支付 → 回调验签 → 入账；
- 线下支付：上传付款凭证 → 财务审核 → 入账/驳回；
- 所有方式均生成充值单、资产流水和审计记录。

## 5. UI 统一验收

- 使用统一校园风变量、圆角、卡片层级、按钮高度、标签与状态色，不在单页重复声明互相冲突的全局样式。
- 主操作清晰且每屏最多一个高强调按钮；危险操作必须二次确认并说明后果。
- 所有图标、首页图片、轮播、导航、公告与客服二维码从后台装修配置读取，支持默认图和新图预览。
- 文案全部中文；技术状态码只用于日志，不直接展示给用户。
- 375px、430px H5 与微信小程序常见机型不横向溢出；底部导航与安全区不遮挡内容。
- 空态说明原因并给出下一步；失败态保留重试；提交态防重复点击。
