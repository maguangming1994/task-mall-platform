# 管理后台信息架构与操作体验

## 1. 导航结构

| 一级模块 | 核心页面 |
|---|---|
| 工作台 | 核心漏斗、待办审批、账务差异、风险案件、服务告警 |
| 用户中心 | 用户资料、身份、设备、资产、限制、注销、隐私请求、审计 |
| 任务中心 | 任务、版本、预算、领取、提交、审核、申诉、风控、推荐位 |
| 商城中心 | 分类、SPU、SKU、库存、运费模板、购物车异常、履约配置 |
| 订单与售后 | 订单、支付、发货、退款、退货、换货、运费补偿、争议 |
| 资产与财务 | 积分、优惠券、钱包、提现、预算池、支付对账、人工调整 |
| 社区内容 | 帖子、评论、举报、处罚、申诉、内容奖励撤销 |
| 运营与消息 | 通知模板、发送记录、用户触达、活动位、基础数据看板 |
| 配置中心 | 配置草稿、校验、审批、发布、版本差异、回滚 |
| 权限与审计 | 后台账号、角色、权限、审批记录、操作日志、安全事件 |

## 2. 角色与数据权限

- 菜单、页面、按钮、字段、数据范围和导出分别授权；前端隐藏不能代替服务端校验。
- 平台管理员默认只管理本人发布的任务；超级管理员和授权运营角色按职责跨主体管理。
- 客服、仓储、财务和审计只查看完成职责所必需的数据，敏感字段默认脱敏。
- 高风险动作使用近期身份验证、影响预览、原因、二次确认和异人审批。
- 批量操作和导出使用独立权限、数量上限、文件短期有效、水印和完整审计。

## 3. 列表与详情统一体验

- 列表统一提供关键词、状态、时间、业务类型、负责人等筛选，支持保存个人视图和恢复默认。
- 表格状态、金额、积分、时间和公共 ID 使用统一格式；不在同一列混合多个不可排序口径。
- 详情页以“摘要—业务数据—状态时间线—资产流水—审计”为固定结构。
- 操作完成后保留筛选和分页；并发版本冲突提示刷新与差异，不静默覆盖。
- 空列表、无权限、加载失败、部分数据失败和导出处理中均有独立状态。

## 4. 配置与审批

- 配置使用开关、单选、多选、数字+单位、日期范围、类目树和结构化编辑器，禁止任意 JSON 文本作为普通操作入口。
- 保存草稿不影响线上；发布前展示差异、影响对象、生效时间、是否仅影响新业务及回滚点。
- 高风险配置必须由不同人员审批；发布和回滚均生成新版本及缓存刷新事件。
- 资产、预算、退款、清零、冻结、权限和批量发券等操作必须预览执行影响和审批门槛。

## 5. 后台验收标准

- 每个角色只能看到授权菜单、字段和数据，直接请求仍被服务端拒绝。
- 审核员在一个详情页完成材料、历史、风险、决定和理由录入，无需反复跳页。
- 危险动作不会因刷新、重复点击或网络重试重复执行。
- 列表筛选、导出、审批和审计可追溯到请求 ID、操作者、原因和前后值。
