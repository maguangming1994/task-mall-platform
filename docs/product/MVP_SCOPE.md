# MVP 范围冻结清单

## 1. 冻结状态

第二十五组已确认。以下内容形成需求基线 v1 的范围边界；第二十六至第三十二组确认的是设计、技术、验收与实施参数，不自动增加业务功能。

## 2. P0 必须交付闭环

```text
微信/手机号登录与统一账号
  → 任务大厅领取或系统自动加入
  → 提交审核或服务端自动核验
  → 发放积分/优惠券/余额奖励
  → 商城纯积分、纯现金或现金+积分购买
  → 余额全额或微信全额承担现金应付
  → 履约/物流/无需物流/虚拟交付
  → 退款、退货、换货、资产退回和对账
```

P0 同时包含：

- 微信小程序、微信内 H5、微信外通用 H5 和管理后台。
- 用户账号、手机号/微信身份、设备、注销和数据权利入口。
- 后台平台管理员发布任务、任务大厅、名额、预算、提交、审核、申诉和风控。
- 积分批次/欠额、优惠券、用户余额、提现和不可删除资产流水。
- 商品分类、SPU、SKU、库存、购物车、订单、支付、运费和售后。
- 社区帖子、评论、举报、内容审核、奖励撤销和申诉。
- 配置中心、RBAC、审批、审计、通知、基础看板、对账和异常补偿。
- 隐私/用户协议入口、第三方清单、客服与投诉入口。

## 3. MVP 明确不做

- 普通用户或机构发布任务，以及多商户入驻、店铺、商家结算和保证金。
- 分销、代理、拼团、秒杀、砍价、预售、复杂会员等级和复杂优惠叠加。
- 即时聊天、私信、直播、完整社交动态和用户之间资金/积分转账。
- AI 自动认定违规、AI 永久处罚、复杂个性化推荐和不可解释的自动审批。
- Android/iOS 原生应用正式上架；uni-app 保留未来编译能力，但不进入首发验收。
- 微服务、跨地域多活、数据仓库、复杂推荐平台和不必要的中间件。
- 用户自由调整现金与积分抵扣比例；混合价由 SKU 固定配置。
- 余额与微信组合承担同一订单现金应付。
- 跨 SKU 换货、售后候补队列和任务满额排队。
- 校园跑腿、快递代取、代买代送、骑手/跑腿员角色、抢单半径、位置轨迹、配送调度和线下到场履约；商城实物商品的标准物流配送不受此条影响。

## 4. 延后但预留

- 受邀机构、认证个人和开放申请的外部任务发布阶段。
- App 正式发布、多商户、会员/营销增强、智能推荐和更复杂的数据分析。
- 预留必须表现为稳定枚举、模块边界、功能开关或扩展字段，不建设首发无调用的完整业务链路。

## 5. 范围变更流程

冻结后新增或恢复一项功能，必须记录：

- 用户问题、预期收益和成功指标。
- 产品、设计、前端、服务端、测试、运维及合规工作量。
- 数据模型、OpenAPI、状态机、资产账务和历史兼容影响。
- 第三方资质、费用、安全、隐私和运营风险。
- 对当前迭代、测试范围和预计发布日期的影响。
- 决策人、结论、进入版本和可回退方案。

未经评估的新增需求进入下一版本候选，不插入当前 P0 主链路。功能开关可以控制新能力放量，但不能替代账务迁移、数据兼容和回滚设计。
