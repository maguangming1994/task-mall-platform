# School coordinates and branding

## What is and is not verified

The MOE 2026 catalog contains 3,196 institutions, but does not publish campus GPS
coordinates. Never copy a city centroid into `campuses.latitude/longitude`.

`database/data/campus_reference_locations.json` contains 2,386 reference POIs for
1,804 exact-name, same-province/city catalog matches. Its source is
[ZsTs119/china-university-database](https://github.com/ZsTs119/china-university-database)
at `36710b5c75779ce50a2ac552924851df54fabf42` (repository revision July 1, 2025).
The upstream README declares MIT; its factual POIs originate from Baidu Place v2.
The original observation dates are unknown. The revision date is NOT an assertion
that every campus was checked in 2025 or is still operating at that address.
Do not describe this snapshot as an officially verified complete campus directory.

Matching accepts a complete school name or a campus suffix, not departments,
schools with similar names, renamed institutions or cross-city branches. Imported
BD09 values are converted offline with pinned MIT-licensed `gcoord@1.0.7` to WGS84,
the coordinate system used by `uni.getLocation`. Source SHA256 is enforced by the
build script. These positions are approximate reference points, not navigation
destinations. Multi-campus schools use the closest matching point for each request.

Order of precedence: admin-maintained WGS84 coordinates, reference school POIs,
city-only discovery, unavailable. City-only candidates always have null distances.
Within 50 km, school positions take precedence over city centroids. Manual
coordinates and operational fields are never overwritten by this snapshot.

The remaining 1,392 institutions need updated official campus information or an
authorized geocoding provider and review. Do not use fuzzy name matching to hide
this gap. `artifacts/campus-location-missing.json` is generated by the build script.
Administrators can view reference campus names, addresses and coordinates in
School Management and explicitly adopt a reviewed point; saving makes it a manual
override. Keep both latitude and longitude in WGS84.

## Reproduce the reference snapshot

Download `public/大学.json` from the pinned repository revision above (not mutable
main). Then run `node scripts/build-campus-locations.mjs <downloaded-file>`.
The script checks the expected source hash before producing the snapshot.

## School emblems

Existing package: `database/data/campus-emblems/manifest.json` (764 schools).
Supplement: `database/data/campus-emblems-supplement/manifest.json`, matched to
current catalog names and provinces using the public Chinese Education Online
college directory. Each supplemental item records the original public image URL
and SHA256. School trademarks remain owned by their institutions; this is identity
display, not an endorsement or a blanket MIT license for the emblems.

The supplement contains 2,103 additional emblems, for 2,867 covered institutions;
329 remain unmatched. Two provider placeholder images were explicitly excluded.
Binary images live on the isolated `data/campus-emblems-20260928` branch, pinned by
the main manifest's `asset_commit`. Do not merge that branch into main: doing so
would add 60 MB to the server's incremental SSH release bundle. API CI and the
production image build run `node scripts/restore-campus-emblems.mjs`, restoring
only manifest-listed images and verifying SHA256 and format before use. Local
developers run the same command before API tests or Docker builds. Production
receives those images via the private Tencent registry, not Git or remote URLs.
Never delete the pinned asset branch while a supported release references it.

`node scripts/collect-campus-emblems.mjs` performs bounded, sequential requests,
skips unknown formats/errors, retains the existing package, and records missing
schools and errors in `artifacts/`. Raw responses are cached under `.runtime-logs/`.
Clear only that specific list cache when intentionally collecting a newer catalog.
Collection intentionally removes the asset pin: a new collection must be reviewed,
published as another immutable asset commit, and explicitly pinned before release.

On deployment the supplemental package is imported locally, without third-party
network requests. A manifest-content cache marker skips a successfully processed
package on later deployments. This adds no public write endpoint. Import is locked,
bounded to 600 seconds, preserves manually configured branding and keeps per-image
provenance. A failure does not mark the package complete. Rerunning is idempotent.
Set `SYNC_CAMPUS_BRANDING_SUPPLEMENT_ON_DEPLOY=false` to opt out of this deployment
step when performing emergency service-only releases.

Commands inside the API container:

```sh
php artisan campuses:sync-branding --supplement --dry-run
php artisan campuses:sync-branding --supplement --once
```

Older local image assets may still store `http://<server-ip>/storage/media/...`.
Public and admin campus responses now derive the HTTPS site URL only when the
asset is local and its stored URL path exactly matches its actual object path.
External CDN URLs are preserved; inactive assets are not revived. No database
rewrite, public storage expansion, or mini-program domain-check bypass is needed.
