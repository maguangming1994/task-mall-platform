# 竞品任务运营规则采纳与业务场景重构

> 状态：已纳入产品基线  
> 适用端：微信小程序、微信公众号 H5、普通浏览器 H5、PC 管理端  
> 核心原则：借鉴信息结构和操作效率，不复制付费层级、永久分成、押金奖池及过度采集身份信息等高风险模式。

## 1. 竞品能力采纳结论

| 竞品能力 | 结论 | 本项目实现方式 |
| --- | --- | --- |
| 今日新增、任务领取、订单、提现等概览 | 采纳 | 后台“用户运营中心”提供当天、累计与近 7 日趋势 |
| 待审核、待发布、库存预警、提现、投诉、履约 | 采纳 | 汇总为可点击的待办指标，后续按权限跳转对应工作台 |
| 用户搜索、状态、验证、时间筛选 | 采纳并加强隐私 | 手机号默认脱敏；精确检索使用哈希；批量导出默认关闭 |
| 用户等级 | 改造后采纳 | 改为免费成长等级，只按资料、审核通过任务和真实现金订单计算 |
| 邀请明细与收益 | 改造后采纳 | 仅记录一级邀请；首次任务和首笔真实现金订单均完成后发放积分 |
| 身份证号码和正反面原图列表 | 不采纳 | 当前只做手机号、资料、微信绑定验证；确需实名时接入持牌服务并只保存结果摘要 |
| 购买会员、出售等级 | 不采纳 | 不通过付费获得任务权限或收益权 |
| 永久收益分成、多级佣金、团队奖励 | 不采纳 | 不设置永久或多级拉新分成，不以发展人员数量作为收益依据 |
| 参与押金、随机瓜分奖池 | 不采纳 | 任务只锁定发布方奖励预算，不向做任务的用户收取参与押金 |
| 发布任务的分步填写与预付预算 | 采纳并重构 | 使用五步发布向导，发布预算进入平台预算池并全程可审计 |

## 2. 四类业务场景

### 2.1 平台任务 `platform_task`

- 发布主体：后台平台管理员。
- 用途：新手引导、社区成长、商城体验、调研、运营活动。
- 验证：可人工审核，也可由可信业务事件自动验证。
- 奖励：积分、优惠券或余额；奖励来源必须绑定平台预算池。

### 2.2 用户悬赏 `user_bounty`

- 当前发布主体：仅具有后台账号和发布权限的平台管理员，可从用户前端进入发布界面。
- 后续开放普通用户发布时，必须新增发布者认证、行业准入、充值结算、发票与纠纷责任能力，不默认开放。
- 用途：需要用户按步骤提交文字、图片或链接作为验收材料的任务。
- 验证：默认人工审核；所有驳回必须填写原因并允许在期限内申诉。
- 奖励：积分或余额。领取时预占单份奖励，审核通过才结算。

### 2.3 成长挑战 `growth_challenge`

- 发布主体：平台运营。
- 用途：每日签到、连续签到、完成若干任务、首次提现等里程碑。
- 验证：必须基于站内可信事件自动验证，不要求用户反复上传截图。
- 奖励：固定奖励或阶段奖励；不收押金、不做随机瓜分。

### 2.4 邀请里程碑 `referral_milestone`

- 发布主体：系统规则，不允许人工创建同名现金拉新任务。
- 达标条件：受邀用户完成第一次审核通过的任务，并完成第一笔真实现金订单。
- 奖励：默认积分；奖励值、每月奖励人数上限均由后台配置。
- 关系范围：只统计直接邀请，不形成多级团队或永久收益关系。

## 3. 发布悬赏五步流程

### 第一步：基础信息与场景

字段包括：业务场景、任务分类、支持设备、封面、任务标题、项目名称、说明和标签。

规则：

- 支持设备只保存 `android`、`ios` 两个原子值，“全部”是两者同时选中。
- 标题用于大厅列表快速识别；项目名称用于发布方内部归档，两者不得混为一个字段。
- 说明不得包含诱导付款、站外转账、索取密码或绕过平台的内容。
- URL 必须为 HTTPS；发布前进入内容与域名风险扫描。

### 第二步：领取、完成与审核

字段包括：可领取天数、领取后完成时限、审核时限、最多提交次数、每人频次。

频次：

- `one_time`：每个账号只可领取一次。
- `daily`：按自然日重置。
- `weekly`：按自然周重置。
- `repeatable`：仅为受控活动保留，必须同时配置周期配额；普通发布默认不展示。

规则：领取成功即生成奖励预占；超时未提交或主动放弃则释放预占。审核超时进入管理端待办和升级提醒，不自动判为用户失败。

### 第三步：奖励与预算

计算公式：

`需锁定预算 = 单份奖励 × 可领取份数`

规则：

- 积分任务绑定积分预算池；余额任务绑定现金预算池。
- 当前平台服务费为 0，不能把“预付赏金”伪装成参与用户押金。
- 创建草稿不扣减预算；申请发布时校验余额并锁定预算。
- 领取时从锁定预算中预占，审核通过转为已发放，释放/关闭时归还未使用预算。
- 余额奖励或总预算超过后台阈值时，必须触发财务与运营双人复核。

### 第四步：做单与验收步骤

每步包含：标题、说明、输入类型、是否必填、访问链接、复制内容和示例图。

输入类型：无需提交、文字、图片、文字和图片、结果链接。最多 20 步。

规则：

- 用户提交页必须按步骤呈现，不能只收一张无法定位步骤的汇总截图。
- 示例图只用于说明，不得遮挡或预填用户的真实凭证。
- 涉及订单或物流时只收必要字段，默认遮挡姓名、手机号、地址、订单号中非必要部分。
- 任务版本若修改说明、步骤、设备、奖励、时效或规则，均视为重大变更；已领取用户继续使用领取时快照。

### 第五步：发布前确认

必须展示业务场景、设备、时效、频次、奖励、数量、锁定预算和步骤数量，并确认：

1. 不要求用户垫资、转账或支付参与押金；
2. 不索取账号密码、支付密码、短信验证码等敏感信息；
3. 接受平台审核、风控、暂停、关闭及纠纷处理规则。

保存草稿和申请发布是两个独立动作。申请发布执行准入扫描、预算校验和分级审核。

## 4. 状态与资金闭环

| 事件 | 任务状态 | 奖励预算处理 | 用户侧结果 |
| --- | --- | --- | --- |
| 保存草稿 | `draft` | 不锁定 | 大厅不可见 |
| 申请发布 | `pending_approval` 或 `published` | 校验并锁定总预算 | 审核通过后可领取 |
| 用户领取 | `published` | 预占一份奖励 | 生成领取记录和完成倒计时 |
| 用户提交 | `published` | 保持预占 | 进入审核队列 |
| 审核通过 | `published` | 预占转已发放 | 奖励到账 |
| 驳回且申诉结束 | `published` | 释放该份预占 | 不发奖励，保留证据与审计 |
| 暂停 | `paused` | 不新增预占 | 已领取任务按公告策略继续或终止 |
| 关闭/到期 | `closed` | 释放未分配预算 | 禁止新领取，已领取按关闭策略处理 |

关闭已有人领取的悬赏时必须明确选择：继续履约、无责终止、补偿终止。任何终止和预算释放都写入审计日志。

## 5. 后台配置项

以下参数必须可在配置中心修改，并保留版本、修改原因、审批和回滚记录：

- 是否开放自主注册；
- 成长等级开关及任务/订单门槛；
- 邀请奖励积分和每月奖励人数上限；
- 默认完成时限、审核时限、申诉期限和提交次数；
- 余额奖励单份复核阈值、任务总预算复核阈值；
- 单任务最大数量、单用户频次、步骤数和附件数；
- 低预算预警线、审核超时升级线；
- 可用任务分类、风险关键词、外链白名单和支持设备。

## 6. 权限与审计

- 当前只有 `platform_admin` 及具备任务创建权限的更高角色可从前端发布悬赏。
- 创建、编辑、申请发布、复核、暂停、关闭、预算锁定/释放均记录操作者、前后值、原因和幂等键。
- 发布人不能独自批准自己触发财务阈值的任务。
- 用户资产调整、敏感资料查看和导出使用独立权限，不因拥有任务发布权自动获得。
