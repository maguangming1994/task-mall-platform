# 任务系统组合基线

> 状态：已确认并纳入产品基线  
> 确认日期：2026-08-13  
> 适用端：微信小程序、微信公众号 H5、普通浏览器 H5、PC 管理端

## 1. 最终组合

本项目继续使用现有 Laravel 任务模块作为唯一业务实现，不整体引入或替换为第三方任务系统。产品能力按以下来源吸收成熟模式：

| 来源 | 采纳范围 | 在本项目中的落点 |
| --- | --- | --- |
| 现有 Laravel 任务模块 | 任务定义、RBAC、预算、用户任务快照、奖励和审计 | 作为唯一领域模型、API 和数据事实来源 |
| Microworkers | 悬赏发布、证明材料、人工审核、驳回补交、审核反馈和辅助核验 | `claim_and_submit` 人工提交任务与后台审核工作台 |
| HOT Tasking Manager | 原子领取、名额占位、处理与验证分离、返工和质量控制 | 用户任务领取状态机、审核分派和复核约束 |
| PYBOSSA | 任务模板、批次数据、动态数据项和结果导出 | 任务模板中心、批次任务和数据项分配 |
| Donetick | 周期调度、子步骤、成长积分、提醒和进度统计 | 每日/每周/里程碑成长任务与自动核验 |

## 2. 明确不做

本项目不是校园跑腿、外卖、配送或线下服务撮合平台，当前及本阶段明确不增加：

- 快递代取、代买、代送、排队、搬运等跑腿任务；
- 抢单大厅、骑手/跑腿员角色、接单半径和配送调度；
- 取件地址、送达地址、实时定位、路线、距离和重量计价；
- 到场签到、取货码、送达码、线下交接和配送凭证；
- 发布人与跑腿员之间的线下服务费、运费或配送结算；
- 因线下履约产生的接送、货损、代购物品和人身安全责任流程。

任务可以要求用户完成站内或经过白名单审查的线上操作，但不得借任务步骤变相实现线下跑腿撮合。后续若确需线下业务，必须作为独立产品变更重新评估地图资质、隐私、安全、保险、结算和责任边界，不能直接扩展当前任务字段。

## 3. 统一领域结构

### 3.1 任务定义层

每个任务定义包含：

- 业务场景、分类、周期、参与方式和核验方式；
- 标题、说明、标签、封面、资格、名额和各类截止时间；
- 奖励组件、预算池、预算锁定规则和风险等级；
- 任务步骤、提交字段、示例材料、审核标准和申诉规则；
- 模板来源、批次来源、版本号和发布快照。

### 3.2 任务模板层

模板保存可复用的任务骨架，不保存某次发布的实际预算占用：

- 基础信息模板；
- 步骤和提交材料模板；
- 资格与频次模板；
- 审核标准和驳回原因模板；
- 默认奖励结构和风险配置。

从模板创建任务后生成独立草稿。模板后续修改不得影响已创建草稿、已发布任务和已领取用户快照。

### 3.3 批次数据层

一个任务定义可以绑定一个或多个数据批次。批次包含若干可分配数据项，例如不同问卷对象、页面、商品或研究样本：

- 支持 CSV/XLSX 导入、字段映射、预检、失败行下载和批次撤销；
- 领取时按任务规则原子分配数据项，同一数据项不得超出配置的最大分配次数；
- 数据项分配结果写入用户任务快照，后续批次修改不影响已领取用户；
- 支持顺序、随机、分层抽样和指定用户四种分配策略；
- 任务结果可以按任务、批次、数据项和审核状态导出。

首版批次字段只支持普通文本、数字、选项、HTTPS 链接和素材引用，不允许导入密码、验证码、完整身份证号等敏感数据。

## 4. 三条任务执行路径

### 4.1 人工提交悬赏

```text
任务发布并锁定预算
  → 用户资格校验
  → 原子领取、占用名额和奖励份额
  → 分配批次数据项（如有）
  → 按步骤执行并保存草稿
  → 提交文字/图片/文件/结果链接
  → 自动预检
  → 审核员人工审核
  → 通过发奖 / 驳回补交 / 最终驳回后申诉
```

规则：

- 自动预检只提供重复度、OCR、文件安全、字段完整性和规则命中提示，不能替代需要人工判断的最终审核；
- 驳回必须选择结构化原因并填写用户可读说明，明确需要修改的步骤；
- 每次提交形成只追加版本，审核材料和历史结论不得覆盖；
- 发布人、执行人和高风险任务最终审核人按权限要求相互分离。

### 4.2 站内行为自动核验

```text
用户领取或系统自动加入
  → 订阅可信业务事件
  → 按周期和幂等键累计进度
  → 达成目标
  → 风控校验
  → 自动完成并发奖
  → 异常进入运营核查
```

自动核验只使用服务端可信事件，不要求用户补交截图证明订单、签到、邀请、资料完善、发帖或评论等站内事实。

### 4.3 周期成长任务

```text
周期开始生成用户进度
  → 展示阶段目标和子步骤
  → 可信事件更新进度
  → 达成阶段或整期目标
  → 发放阶段/最终奖励
  → 周期结算并生成下一周期
```

支持一次性、每日、每周、每月和里程碑周期。周期重置只重置进度实例，不修改历史完成与奖励流水。成长任务不得使用虚假完成数、随机瓜分或参与押金刺激用户。

## 5. 领取与验证状态机

### 5.1 用户任务状态

| 中文状态 | 内部状态 | 说明 |
| --- | --- | --- |
| 待开始 | `reserved` | 名额和奖励已预占，尚未开始执行 |
| 进行中 | `in_progress` | 用户已开始执行或保存步骤草稿 |
| 待提交 | `ready_to_submit` | 必做步骤已完成，可发起提交 |
| 审核中 | `under_review` | 已提交并进入审核队列 |
| 待补充 | `revision_required` | 审核驳回但仍在重提期限和次数内 |
| 申诉中 | `under_appeal` | 用户已对最终审核结果发起申诉 |
| 已完成 | `completed` | 核验通过，奖励进入发放流程 |
| 已放弃 | `abandoned` | 用户主动放弃，按规则释放占位 |
| 已过期 | `expired` | 未在完成期限内提交 |
| 已关闭 | `terminated` | 平台按任务关闭策略终止该用户任务 |

### 5.2 审核状态

| 中文状态 | 内部状态 | 说明 |
| --- | --- | --- |
| 待分派 | `unassigned` | 尚未确定审核员 |
| 待审核 | `queued` | 已进入审核员工作队列 |
| 审核中 | `reviewing` | 审核员已打开并占用审核会话 |
| 需要补充 | `needs_revision` | 指定步骤材料需要补充 |
| 审核通过 | `approved` | 满足验收标准 |
| 最终驳回 | `rejected` | 无重提机会，可按规则申诉 |
| 已撤销 | `voided` | 提交被用户撤回或因任务终止失效 |

领取、提交、审核、申诉和发奖分别保存状态，不用一个字段表示全部过程。

## 6. 审核工作台

后台审核工作台至少提供：

- 按任务、批次、步骤、提交时间、审核期限、风险等级和材料类型筛选；
- 左侧任务标准，中间用户材料，右侧审核结论的三栏核对模式；
- 图片缩放、旋转、并排对比、OCR 文本和相似材料提示；
- 按步骤通过或标记问题，整单提交最终结论；
- 常用驳回原因模板和面向用户的修改说明；
- 审核占用、防止多人重复处理、转派、升级和逾期提醒；
- 批量操作仅限低风险且规则一致的提交，高风险任务禁止无差别批量通过；
- 原审核人与申诉审核人分离，所有查看和操作写入审计日志。

## 7. 后台新增模块

| 模块 | 核心能力 |
| --- | --- |
| 任务模板中心 | 新增、复制、编辑、停用、版本、从模板创建任务 |
| 批次与数据项 | 导入、字段映射、预检、分配策略、使用情况、结果导出 |
| 审核工作台 | 队列、材料核对、驳回补交、转派、逾期和申诉入口 |
| 周期任务中心 | 周期、目标、阶段、重置、补算、事件来源和异常记录 |
| 质量与风控 | 通过率、驳回率、重复材料、异常账号和审核一致性 |

## 8. 首批实施顺序

1. 固化用户任务与审核双状态机，并补齐状态迁移测试；
2. 建立任务模板、模板版本和“从模板创建草稿”；
3. 改造审核工作台，先完成按步骤审核和驳回补交；
4. 建立批次、数据项导入与领取时原子分配；
5. 扩展每日、每周、每月和里程碑周期任务；
6. 增加 OCR/重复材料等辅助预检与质量看板；
7. 更新 uni-app 任务大厅、我的任务、任务执行和提交状态页面；
8. 更新在线 UI 总览和后台原型，完成多角色评审后再进入正式页面开发。

## 9. 验收标准

- 并发领取不会突破名额、预算或数据项分配上限；
- 模板或批次修改不影响已领取用户的不可变快照；
- 人工任务的每个必做步骤都能对应到提交材料和审核结论；
- 周期任务跨周期不重复计奖，历史进度和奖励可追溯；
- 驳回补交、最终驳回和申诉的人员、时限与材料版本完整可查；
- 用户端和后台全部显示中文业务状态，内部枚举不直接暴露；
- 系统不存在跑腿角色、配送调度、线下地点与到场履约入口。
