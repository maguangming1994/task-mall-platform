# 普通用户与机构任务发布边界

## 1. 当前结论

- 首发版本继续只允许持有后台账号和平台管理员角色的人员发布任务。
- 普通用户、机构、商家和其他第三方不显示申请或发布入口，也不能调用平台管理员发布接口。
- 数据模型可以预留 `user` 和 `organization` 发布主体，但对应状态必须保持禁用。
- 对外开放发布属于独立产品里程碑，不是一个普通配置开关；没有通过产品、法务、财务、安全和运营评审时，系统只能保持 `closed`。

## 2. 分阶段开放

未来只允许按以下顺序灰度，不一次性全面开放：

1. `closed`：首发状态，仅平台管理员。
2. `invited_organizations`：受邀且完成认证的机构，小范围白名单。
3. `verified_users`：受限的认证个人申请，低额度、低频次。
4. `open_applications`：面向普通用户或机构开放申请，但仍需审核和分级授权。

每次阶段升级必须有独立发布单、影响评估、灰度范围、监控指标和一键停止新发布方案；降级只阻止新申请和新发布，不直接终止已经参与用户的任务。

## 3. 主体申请与资质

- 个人发布者至少完成已验证手机号、实名校验、发布协议签署和风险评估。
- 机构发布者还需提交主体名称、统一社会信用代码、授权经办人和必要行业资质。
- 资质具有审核状态、适用任务类别、有效期和复审日期；过期后停止新发布，已发布任务进入人工处置队列。
- 平台保存必要的资质结果和脱敏摘要；原始材料使用独立权限、加密存储和访问审计。
- 禁止行业和任务类别由独立规则维护，不能通过修改任务分类绕过。

## 4. 奖励资金边界

- 非平台发布者必须在发布前预付并锁定完整奖励预算，任一奖励组件不足都不能提交审核。
- 发布者预付奖励资金使用独立资金账户和不可删除流水，不属于用户商城钱包，也不能直接使用用户钱包余额发奖。
- 首期只允许平台积分、平台优惠券和预付余额奖励；禁止私下转账、外部红包、实物承诺或其他不可审计奖励。
- 任务结清且无投诉、申诉、奖励重试和争议后，未使用资金按已审核规则退回经验证的原资金路径。
- 争议中的预算继续冻结；发布者不能绕过平台要求用户先行垫付或在站外结算。
- 服务费、税务、发票、资金路径、退款周期和会计口径必须在开放前单独确认。
- 首期不默认设计“保证金”；如后续需要，必须在法务和支付评审后与奖励预付资金分账管理。

## 5. 发布审核与额度

- 所有非平台发布者任务在上线前必须人工审核，不适用平台管理员低风险任务直发规则。
- 新发布者默认使用最低等级：限制同时在线任务数、单任务人数、单笔奖励、总预算和允许类别。
- 平台根据认证、履约、投诉、申诉、退款、作弊和历史处罚调整发布等级；自动评分只能建议，不能单独作出永久封禁。
- 发布者不能审批自己的任务、推荐位、投诉、风险案件或额度提升申请。
- 超限发布、资质变更、高风险类别和重大修改需要更高权限审核。

## 6. 数据与用户保护

- 发布者只查看完成审核所必需的结构化结果，不默认获得用户手机号、设备、支付身份、地址或其他敏感信息。
- 首版禁止发布者批量下载任务材料；确需导出必须单独授权、脱敏、水印并记录审计。
- 任务详情展示发布主体名称、主体类型、认证状态、平台审核标识和举报入口。
- 平台统一处理用户投诉、申诉、奖励补偿和发布者争议，发布者不得要求用户转移到私人联系方式处理。

## 7. 处罚与退出

- 处罚分为提醒、降低额度、限制类别、暂停新发布、冻结预算、关闭任务和永久取消发布资格。
- 风险处置遵循证据留存、人工复核和异人申诉；紧急风险可先隐藏、停领和冻结奖励。
- 发布资格停止后，未结任务按照继续履约、平台接管或终止补偿策略逐项处理，不能批量直接删除。
- 发布者退出前必须完成任务、奖励、投诉、退款、发票和资金账户结算。

## 8. 上线硬门槛

开放阶段不为 `closed` 前，必须同时具备：

- 主体申请、认证、资质到期和复审流程。
- 独立预付资金账本、预算锁定、退款、对账和争议冻结能力。
- 非平台任务百分之百人工发布审核以及职责分离。
- 额度、行业、内容、隐私、材料和多账号风控。
- 用户端主体标识、举报、投诉、申诉和补偿闭环。
- 法务、财务、税务、隐私、安全和运营联合签字，以及灰度停止与回滚预案。

以上任一项未完成时，服务端能力响应必须保持外部发布关闭。
