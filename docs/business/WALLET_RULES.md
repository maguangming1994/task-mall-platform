# 用户余额、支付与提现规则

## 1. 余额性质

- 任务余额奖励进入用户钱包，单位为人民币分。
- 余额永久有效，不设置过期时间。
- 余额可以支付商城订单，也允许申请提现。
- 余额、积分、优惠券和第三方支付分别记账，不混用流水。
- 钱包汇总余额可以缓存，但必须能够由不可删除的流水重新计算。

## 2. 余额支付

商品购买方式仍然只有纯积分、纯现金、现金加积分三种。余额属于现金应付部分的资金来源：

```text
商品现金应付
  - 优惠券现金抵扣
  + 现金运费
  = 最终现金应付

最终现金应付只能二选一：余额全额支付 / 微信全额支付
```

- 纯积分订单没有现金应付，不能额外使用余额。
- 纯现金和现金加积分订单可以使用余额。
- 用户在余额支付和微信支付中单选，不能同时使用。
- 选择余额时，余额必须覆盖全部最终现金应付，包括运费；余额不足时禁止选择余额支付。
- 选择微信时不扣除或冻结任何余额，全部最终现金应付走微信支付。
- 余额支付时在创建订单事务中校验并冻结全部现金应付，订单创建成功后立即完成余额扣除，订单进入待履约。
- 微信支付时不冻结余额，订单等待微信支付；取消或超时只释放库存和积分冻结。
- 余额支付订单不创建微信支付单，微信支付订单不创建钱包冻结流水。

## 3. 退款

- 余额支付订单的现金退款全部退回余额账户。
- 微信支付订单的现金退款全部通过原支付渠道退款。
- 积分支付部分退回积分账户并重新计算有效期。
- 一个订单的现金资金来源只能有一种，因此部分退款不在余额与微信之间分摊。
- 钱包退款、微信退款和积分退款分别记录组件状态，失败部分可以单独重试。

## 4. 提现流程

```text
用户申请 → 校验可用余额 → 冻结余额 → 风控/审核
        → 提现渠道处理 → 成功扣除 / 失败解冻
```

提现渠道使用适配器，首发预留微信商家转账，后续可以增加其他渠道。

提现单至少保存：申请金额、手续费、实际到账、渠道、收款身份、状态、第三方单号、失败原因、审核人和时间。

手续费默认费率为千分之六（0.6%），后台可以修改。计算规则：

```text
手续费 = 申请提现金额 × 手续费率，按人民币分向上取整
实际到账 = 申请提现金额 - 手续费
```

提现成功后钱包总扣减等于申请提现金额，不额外再扣一笔手续费。提交申请前必须向用户展示申请金额、手续费和预计到账金额。

提现状态：

- `created`：已创建。
- `reviewing`：风控或人工审核。
- `processing`：已提交渠道。
- `awaiting_user_confirmation`：等待用户确认收款。
- `succeeded`：提现成功，冻结余额正式扣除。
- `rejected`：审核拒绝并解冻。
- `failed`：渠道失败并解冻。
- `cancelled`：提交渠道前取消并解冻。

## 5. 后台用户资产操作

用户列表和用户详情提供资产入口，可查看：

- 可用积分、冻结积分和积分批次
- 可用余额、冻结余额和钱包流水
- 可用、锁定、已使用和过期优惠券

允许的后台操作：

- 积分增加、减少、清零
- 余额增加、减少、清零
- 优惠券发放和撤销

所有操作必须填写原因。减少不能超过可用资产；冻结中的积分或余额不能直接清零。

“清零”不允许执行数据库覆盖更新，而是创建一笔等于当前可用值相反数的调整流水。历史流水、订单、支付和提现记录永远不能被清除。

高风险调整进入审批流，审批门槛由后台配置。余额操作由财务或超级管理员执行，客服只有查看和发起申请权限。

## 6. 后台配置

- 余额支付是否启用
- 结算页使用余额支付或微信支付单选，不允许余额与微信组合
- 提现是否启用及渠道
- 单笔最低和最高提现金额
- 每日提现次数和金额上限
- 提现手续费率，默认千分之六
- 自动审核和人工审核规则
- 单次余额奖励上限
- 后台余额调整二次审核门槛
- 清零是否始终需要二次审核
