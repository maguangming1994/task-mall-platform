# 用户角色与后台权限

MVP 为平台自营商城，不开放第三方商家入驻。后台采用 RBAC，并为高风险动作增加单独权限和二次审核。

普通用户仅访问自己的任务、社区、积分、优惠券、订单和售后数据。

平台管理员是后台账号角色，不是普通用户等级。该角色默认包含 `task.frontend_publish` 权限，可以在用户端任务发布中心操作本人发布的任务；运营管理员不会因拥有后台任务管理权限而自动获得这一前端入口。超级管理员拥有授权和应急管理能力。

未来的个人或机构发布者是外部业务主体，不是后台角色，不获得后台菜单、平台预算池、全局任务管理或审核权限。其申请、资质、额度和预付资金权限使用独立授权模型；首发状态下该模型只做数据预留并保持禁用。

## 2. 高风险操作

- 现金退款必须先通过售后审核。
- 单笔现金退款超过 200 元，需要财务二次审核。
- 单次人工调整超过 1000 积分，需要超级管理员二次审核。
- 单次余额增加或减少超过 200 元，需要财务二次审核。
- 余额清零无论金额都需要二次审核。
- 批量发放优惠券超过 1000 人，需要超级管理员确认。
- 库存调整必须填写原因、调整数量和调整前后快照。
- 修改角色、权限、积分规则和支付配置必须记录变更前后值。
- 客服可以初审和判责，但不能直接修改支付、积分或库存流水。
- 用户资产增加、减少和清零由财务或超级管理员执行；客服只能查看或发起调整申请。

门槛数值通过后台系统配置保存，但修改门槛本身只允许超级管理员操作。

## 3. 隐私数据权限

- 手机号、详细地址和身份关联信息默认脱敏。
- 仓储人员仅在履约所需范围查看收件信息。
- 查看完整手机号、完整地址和导出用户数据使用独立权限。
- 每次查看或导出敏感信息记录操作人、对象、原因、IP 和请求 ID。
- 审计人员可查看脱敏业务信息和审计记录，不能执行写操作。

## 4. 登录安全

- 超级管理员和财务人员启用更严格的登录验证。
- 后台会话设置空闲超时和最长有效期。
- 角色或账号被禁用后，现有会话立即失效。
- 连续登录失败触发限流、验证码或临时锁定。
- 高风险操作要求近期重新验证身份。
- 用户端任务发布使用独立、短时、限权的管理员发布会话；普通用户会话和发布会话不能互换。
- 发布会话只能调用任务发布接口，不得复用为用户、资产、支付、权限或系统配置管理会话。
- 任务风险审核、紧急隐藏、奖励冻结、发布权限处罚和风险申诉使用独立权限；发布者、原处理人和申诉复核人按职责分离。
- 永久或长期账号处罚不能只由自动规则执行，必须记录人工结论和证据摘要。

## 5. 审批记录

二次审核保存：申请人、审核人、动作类型、业务对象、阈值、申请原因、审核意见、时间和最终执行结果。申请人与二次审核人不能是同一个后台账号。
