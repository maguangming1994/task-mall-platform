# 商城三种购买方式

## 1. 已确认规则

商城支持：

1. 纯积分：只扣积分，不创建第三方现金支付。
2. 纯现金：只通过微信支付现金，不扣积分。
3. 现金加积分：扣除固定积分，同时支付固定现金金额。

MVP 的混合支付金额由后台按 SKU 固定配置，用户不能自由调整积分抵扣数量。同一个 SKU 可以同时开启三种方式，也可以由后台只开启其中一种或两种。

## 2. SKU 配置建议

同一个 SKU 可以开启一种或多种购买方式，每种方式独立配置：

| 购买方式 | 现金金额 | 积分数量 |
|---|---:|---:|
| 纯积分 | 0 | 必填 |
| 纯现金 | 必填 | 0 |
| 现金加积分 | 必填 | 必填 |

现金金额以人民币分整数存储，积分以整数存储。禁止使用浮点数保存价格。

建议使用独立的 SKU 购买方案表，而不是在商品表堆叠价格字段，以便后续控制启用状态、有效期和渠道。

运费始终使用现金支付，不能使用积分抵扣。

用户余额不是第四种购买方式，而是现金应付部分的资金来源。纯现金和现金加积分订单的现金应付只能在余额支付和微信支付中选择一种，禁止余额与微信组合。选择余额时必须覆盖全部现金应付和运费；余额不足只能选择微信。纯积分订单不使用余额或微信。

## 3. 订单必须保存的快照

- 商品与 SKU 名称
- 商品图片
- 规格描述
- 购买方式
- 单价现金金额
- 单价积分数量
- 数量
- 现金小计
- 积分小计
- 运费
- 下单渠道：微信小程序、微信内 H5 或微信外 H5
- 优惠券现金优惠分摊
- 优惠券积分优惠分摊
- 实际支付现金、实际支付积分
- 余额支付金额、外部渠道支付金额

商品后续修改价格或下架，不得改变历史订单。

## 4. 下单处理

### 纯积分

1. 校验商品、库存、限购和积分余额。
2. 预占库存并冻结积分。
3. 创建订单及订单项快照。
4. 订单创建成功后扣除冻结积分，订单进入待发货。
5. 任一步骤失败必须回滚库存和积分。

### 纯现金

1. 校验商品、库存和限购。
2. 预占库存并创建待支付订单。
3. 创建微信支付单。
4. 支付成功后订单进入待发货并正式扣减库存。
5. 订单超时或支付失败后释放库存。

### 现金加积分

1. 校验商品、库存、限购和积分余额。
2. 同时预占库存、冻结积分并创建待支付订单。
3. 创建现金部分的微信支付单。
4. 现金支付成功后扣除冻结积分，订单进入待发货。
5. 现金支付失败或订单超时后释放库存并解冻积分。
6. 回调重复到达时不得重复扣积分或扣库存。

## 5. 优惠券

- 优惠券可以配置现金抵扣额、积分抵扣额，或同时包含两者。
- 每笔订单最多使用一张优惠券，优惠券之间不能叠加。
- 优惠券可配置全部商品、分类、商品或 SKU 适用范围。
- 组合优惠券必须同时满足最低现金和最低积分门槛。
- 现金优惠和积分优惠分别计算、分摊和记录，不能互相换算。
- 优惠按订单项分摊并保存快照，为部分退款提供依据。
- MVP 优惠券只作用于商品，不抵扣运费，确保运费始终使用现金支付。
- 优惠后的现金和积分金额不得小于零。

## 6. 退款与取消

- 未支付现金订单取消：释放库存，混合支付订单同时解冻积分。
- 纯积分订单全额退款：退回实际使用积分，并记录退款积分流水。
- 纯现金订单全额退款：原路退回现金。
- 混合支付订单全额退款：现金原路退回，积分退回积分账户，两部分分别记录状态。
- 支持按商品数量部分退款、整项退款和整单退款。
- 部分退款使用订单项中实际支付的现金、积分和优惠分摊计算，不使用商品当前价格。
- 多次部分退款累计不得超过该订单项实际支付的现金和积分。
- 数量分摊产生的整数余数由该订单项最后一次退款吸收，保证累计账务完全一致。
- 退款积分从实际退回积分账户时重新计算有效期，按照原消费积分对应来源的当前有效期规则生成新批次。
- 整单取消或整单退款成功后返还优惠券；部分退款、整项退款但订单仍保留商品时不返券。
- 实际退货时原订单运费不退；退货运费根据售后原因和最终责任判定，并单独记录。
- 订单不得根据商品当前价格计算退款，只能使用订单快照和实际支付记录。
