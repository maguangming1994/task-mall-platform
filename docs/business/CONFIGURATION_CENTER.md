# 后台配置中心

所有默认参数都必须可以在管理后台查看和修改，业务代码不得散落硬编码数值。

## 1. 配置分类

### 积分与成长

- 全局默认积分有效期 365 天，到期日 23:59:59 失效
- 签到 5/90 天、发帖 10/90 天、评论 2/60 天、资料 100/365 天、推荐 500/365 天等来源默认值
- 每日、每月和累计奖励上限
- 到期前 7 天和 1 天提醒
- 连续签到是否启用及阶梯规则
- 推荐新人达标条件
- 内容删除或违规后是否追回积分
- 欠额抵扣、欠额期间禁止消费和人工减免规则
- 欠额减免超过 1000 积分的超级管理员二次审核门槛

### 任务

- 默认提交次数 3 次及任务级覆盖
- 默认审核期限 48 小时及任务级覆盖
- 默认申诉期限 7 天、申诉次数 1 次及任务级覆盖
- 新手成长、日常、社区、商城、调研和运营活动等任务分类
- 一次性、每日、每周和重复任务开关
- 领取并提交、领取后自动核验、系统自动加入三种参与方式
- 任务大厅栏目、推荐置顶、排序和用户资格模板
- 自动核验事件白名单、目标值、周期去重和异常处理规则
- 有限名额取消/到期后的释放策略，以及自动加入任务的参与人数和奖励预算上限
- 用户端任务发布中心开关、允许角色和 `task.frontend_publish` 权限
- 外部任务发布阶段只读展示 `closed/invited_organizations/verified_users/open_applications`；阶段变更必须走独立上线审批，不能由普通配置发布直接生效
- 非平台发布者申请范围、资质类型、复审期限、禁止行业、任务类别和灰度白名单
- 非平台发布者等级、在线任务数、参与人数、单笔奖励、单任务预算和累计预算上限
- 预付奖励资金、争议冻结、结清退回及非平台任务百分之百人工审核规则
- 发布会话有效期、近期身份验证期限、草稿自动保存和预览有效期
- 前端发布允许的任务分类、奖励类型、单任务预算及必须转后台审批的条件
- 平台积分发行额度、优惠券发行数量和余额现金预算池
- 任务总奖励次数、周期奖励上限、预算预留和释放时机
- 默认完成期限24小时、周期参与次数、重复任务冷却时间和取消后重领策略
- 到期前24小时与2小时提醒、自动加入触发点和满额显示规则
- 任务大厅栏目、推荐权重、置顶数量与有效期、搜索字段和筛选项
- 公开/定向保密任务资格展示、到期隐藏、同屏去重和默认每页20条
- 普通/重大修改字段清单、版本审批、推荐位复核和回滚权限
- 有进行中用户时的关闭审批、履约/终止/补偿策略及归档条件
- 任务风险词库、禁止内容、外链域名白名单、文件安全检查和相似度阈值
- 账号/设备/IP/频率风控、举报原因、高危2小时与普通24小时响应期限
- 奖励冻结、发布者处罚、申诉复核和平台误判补偿策略
- 任务余额总预算财务二审门槛，初始 5000 元
- 预算耗尽停止新参与、预算差异自动停领和告警规则
- 积分、优惠券和余额奖励类型开关
- 单次积分和余额奖励上限
- 文本、图片、视频、文件字段，以及默认 9 张/10 MB、1 个/100 MB、5 个/20 MB 限制
- 用户撤回、驳回重提、暂停和紧急关闭处理方式
- 审核逾期提醒与升级、奖励失败重试和人工补偿规则
- 单用户余额奖励超过 200 元的财务二次审核门槛

### 优惠券

- 默认有效期和返券宽限期
- 现金、积分、组合券类型是否启用
- 使用门槛、适用范围、发行量和每人限领
- 系统、后台、活动发放方式
- 整单返券、部分退款不返券规则

### 订单与支付

- 待支付订单关闭时间
- 库存预占时间，初始 15 分钟；待支付关闭时间初始 15 分钟
- 三类交付方式的履约期限、提醒时间、异常升级时间和自动完成时间
- 默认低库存阈值，初始 10 件，并允许 SKU 覆盖
- 单笔、每日、活动期和终身限购规则，并允许 SKU 覆盖
- 按交付类型拆单的策略和退款后是否恢复限购额度
- 支持的购买方式：纯积分、纯现金、现金加积分
- 支付渠道和使用场景开关
- 余额支付开关；用户端在余额和微信中单选，禁止组合支付
- 三个首发端共用价格，该约束不允许通过普通配置改成渠道价

### 售后与履约

- 售后申请期限、审核期限和寄回期限
- 物流、无需物流、虚拟交付方式开关
- 退货原因的启用、排序和适用类目
- 默认责任方、凭证要求、原运费处理和退货运费承担方
- 运费补偿上限和人工审核门槛
- 是否支持退款、退货退款和换货
- 固定、按件和按重量运费模板及配送区域、偏远地区附加费
- 指定商品、满现金金额和满件包邮规则
- 分批发货、物流承运商、轨迹查询频率和失败重试
- 同 SKU 换货开关、适用类目和往返运费责任
- 退货运费补偿默认每包裹 30 元，超额人工审核

### 权限与风险

- 现金退款二次审核门槛，初始 200 元
- 人工积分调整二次审核门槛，初始 1000 积分
- 批量发券二次确认门槛，初始 1000 人
- 登录失败锁定、验证码和限流参数
- 敏感数据查看和导出权限
- 余额人工调整和大额任务奖励审核门槛

### 账号与用户资料

- 游客可浏览范围、必须登录动作和必须绑定手机号动作
- 小程序、微信内 H5 和微信外 H5 登录方式开关
- 完善资料奖励所需字段
- Access Token 与 Refresh Token 有效期，默认 2 小时和 30 天
- 活跃设备上限及超限退出策略，默认 5 台
- 手机号更换校验和旧手机号不可用时的申诉流程
- 提现收款身份要求及身份变更后的保护期
- 注销资格拦截项、冷静期和剩余积分/优惠券处理，冷静期默认 7 天
- 注销后再次注册与历史身份冲突处理方式

### 多端能力

- 小程序、微信内 H5、微信外 H5 的登录、分享、支付和消息能力开关
- 微信外 H5 手机号登录降级，以及 H5 支付不可用时的余额支付/微信打开提示
- 小程序支付、JSAPI 支付、H5 MWEB 支付的开通和配置状态
- 分享标题、摘要、图片、推荐码有效期和落地页面
- 小程序订阅消息、公众号消息、站内信和短信的端级降级顺序
- 支付域名、授权目录等非机密配置的检查状态；密钥和证书不得放入普通配置

### 用户钱包与提现

- 余额支付和提现功能开关
- 最低、最高提现金额和每日次数
- 提现手续费率和审核方式
- 提现渠道及场景
- 余额增减和清零的二次审核规则

首版初始值为最低 10 元、单笔最高 1000 元、每日最多 3 次且累计 2000 元、手续费千分之六、全部人工审核；余额增减超过 200 元或任何余额清零需要二次审核。

### 通知与内容

- 各业务通知是否启用及发送渠道
- 积分到期提醒时间
- 默认免打扰时间，初始 22:00～08:00
- 外部渠道失败重试次数，初始 3 次
- 必要消息、可选消息和营销订阅规则
- 通知模板草稿、版本、发布和回滚
- 社区发帖、评论是否先审后发
- 图片、视频、文件类型和大小限制
- 举报原因和违规处理方式
- 帖子标题/正文、评论长度、图片数量、视频数量和视频大小
- 社区审核期限、申诉期限和每日发布上限

### 数据与指标

- 北极星指标和各转化指标的展示目标值
- 指标时间窗口、内部/测试账号过滤和异常流量排除规则
- 任务大厅曝光、领取、首次任务完成、发奖、商城访问和首笔现金订单漏斗
- 指标目标值版本、修改原因和看板告警阈值

指标目标值修改只影响看板比较线和告警，不修改历史业务事实，也不重新计算任务、奖励或订单。

## 2. 后台控件

| 参数类型 | 控件 |
|---|---|
| 启用/停用 | 开关 |
| 单一模式或责任方 | 单选框/下拉选择 |
| 多个渠道、类目或商品 | 多选框/树形选择 |
| 金额、积分、天数和次数 | 带单位数字输入框 |
| 开始和结束时间 | 日期时间范围 |
| 规则条件 | 条件配置器 |
| 退货原因排序 | 拖拽排序 |
| 类目适用范围 | 类目树 |

前端显示中文名称和单位，服务端保存稳定代码及标准单位；现金后台显示元，提交 API 和数据库时转换为分。

## 3. 发布流程

```text
编辑草稿 → 校验 → 查看差异 → 审核（高风险）→ 发布 → 生效
                                      ↓
                                   驳回修改
```

- 普通修改可以由有权限的运营人员发布。
- 高风险门槛、支付、权限和账务规则需要超级管理员或对应审核人批准。
- 保存草稿不影响线上配置。
- 发布时生成不可修改的版本和配置快照。
- 允许查看历史版本并回滚；回滚实际生成一个新版本。

## 4. 生效范围

- 积分规则修改只影响修改后产生的新奖励和退款积分批次。
- 任务规则由用户领取时保存快照。
- 商品价格和购买方式由下单时保存快照。
- 优惠券规则由用户领取和下单使用时保存快照。
- 售后原因规则由用户申请时保存快照。
- 已经开始的订单、支付和退款不因后台配置变化而重新计算。

需要追溯修改历史数据时，必须通过单独的数据修正流程和审计审批，不能依赖普通配置发布。

## 5. 数据与缓存

- 领域规则优先使用独立业务表，例如 `point_rules`、`after_sale_reasons` 和 `coupon_templates`。
- 简单全局参数放入类型化系统配置表。
- 应用读取已发布版本并缓存到 Redis。
- 发布成功后使用配置事件清理缓存，多实例同时刷新。
- 配置读取失败时使用最近一次有效版本，不能静默回退到代码默认值。

## 6. 审计要求

记录配置分类、键、修改前后值、草稿人、审核人、发布时间、版本、原因、IP 和请求 ID。密钥和支付证书不作为普通配置展示，只能通过密钥管理方式维护。
