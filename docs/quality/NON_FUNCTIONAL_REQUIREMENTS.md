# 非功能需求基线

## 1. 性能与容量

- 核心 API 在正常目标负载下服务端 p95 不高于 500ms；文件上传、导出、报表和第三方等待使用独立预算。
- 所有分页接口有最大页大小；大批量操作异步执行并返回进度。
- 发布前必须填入预计 DAU、峰值在线、瞬时任务领取人数、日订单量、峰值读写 RPS 和文件量，再据此确定最终压测模型。
- 名额、库存、优惠券、奖励预算、余额和退款在并发下不得超发、重复入账或出现负数。

## 2. 可用性与恢复

- MVP 月可用性目标 99.9%；支付回调、账务写入、任务奖励和订单状态优先保障。
- 初始恢复目标：核心数据 RPO 不高于 15 分钟、RTO 不高于 2 小时，最终方案需结合云资源与预算复核。
- 数据库、对象存储和关键配置有自动备份；按计划执行真实恢复演练，而非只检查备份文件存在。
- 外部服务失败使用超时、有限重试、熔断、降级、查询补偿和人工处理，不无限重试。

## 3. 安全

- 覆盖认证绕过、越权、注入、XSS、CSRF、SSRF、重放、批量遍历、恶意上传和接口滥用。
- 全站 HTTPS；密码使用强哈希；敏感字段加密或脱敏；密钥定期轮换。
- 登录、验证码、上传、领取、支付、提现、退款和导出分别限流并记录风险信号。
- 日志禁止记录密码、验证码、Token、完整证件/银行卡、支付密钥和原始高敏感材料。
- 自动风控不得凭单一信号永久处罚，重大处罚和申诉职责分离。

## 4. 可观测性

- 日志、指标、链路、请求 ID、幂等键、业务公共 ID、领域事件和审计记录可关联。
- 监控 API 错误率/延迟、数据库、Redis、队列、对象存储、支付回调、库存、预算和账务差异。
- 告警有阈值、持续时间、值班人、升级人和处置手册；避免无负责人告警。

## 5. 兼容性与体验

- 微信小程序覆盖常用 iOS/Android 微信版本；H5 覆盖微信内浏览器、Safari、Chrome 和常用 Android WebView。
- 管理后台覆盖 Chrome、Edge 和常用桌面分辨率。
- 弱网、重复点击、页面恢复、前后台切换、授权拒绝和支付结果未知均有恢复路径。
- 首发不验收原生 App 上架，但 uni-app 代码不得直接依赖只在某一端存在的全局能力。
