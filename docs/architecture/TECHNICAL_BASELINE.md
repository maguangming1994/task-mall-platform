# 技术基线、环境与外部服务

## 1. 已确认技术栈

- 用户端：uni-app、Vue 3、TypeScript、Pinia，首发微信小程序与通用 H5。
- 管理后台：React、TypeScript、Ant Design。
- 服务端：PHP、Laravel 模块化单体。
- 数据层：PostgreSQL、Redis、队列和对象存储。
- 契约：OpenAPI 是前后端唯一接口契约，生成客户端类型但不生成未经审查的业务逻辑。

具体运行时和框架小版本在可运行项目初始化时选择届时稳定受支持版本，写入工具版本文件、锁文件和镜像标签；升级必须经过兼容与回归测试。

## 2. 架构原则

- MVP 使用模块化单体，模块拥有明确领域边界；跨模块通过应用服务或领域事件协作。
- 支付回调、通知、奖励发放、文件扫描、物流同步、对账和保留期删除使用可靠队列与幂等消费者。
- 现金、积分、库存、预算和优惠券变更使用数据库事务、唯一键和不可删除流水。
- 外部服务通过适配器接入，业务层不依赖厂商私有字段。
- 不因未来可能拆分微服务而提前复制数据库或引入分布式事务。

## 3. 环境

| 环境 | 用途 | 数据与凭证 |
|---|---|---|
| local | 单机开发与自动测试 | 合成数据、测试凭证、本地替代服务 |
| test | CI、集成和测试团队 | 独立测试数据，不复制生产明文 |
| staging | 发布演练、支付沙箱/受控验证 | 近生产配置，独立账号和脱敏数据 |
| production | 正式业务 | 生产密钥、最小权限、审计和备份 |

本地建议用 Docker Compose 启动 PostgreSQL、Redis 和兼容对象存储；应用运行方式保持与 CI 一致。四套环境的数据库、缓存、存储桶、队列、回调和密钥严格隔离。

## 4. 密钥与配置

- 密钥只进入环境变量或密钥管理服务，不写入 Git、镜像层、前端包、日志和错误响应。
- 配置模板只提供变量名和安全默认值；生产高风险配置通过受控发布流程变更。
- 支付证书、API 密钥和第三方 Token 设置负责人、用途、权限、到期/轮换和撤销记录。

## 5. 外部服务

- 对象存储/CDN、短信、微信登录/支付、提现、物流、地图、客服和监控均建立接口适配器。
- 所有调用设置超时、有限重试、幂等键、熔断/降级和可观测指标。
- 不可用时不得伪造成功；支付和账务进入查询补偿或人工队列。
- 生产供应商、云厂商、服务器地区、域名、对象存储、短信和支付渠道仍需业务方按合规清单提供。

## 6. 工程门槛

CI 至少执行格式化、静态分析、单元测试、OpenAPI 校验、数据库迁移检查、依赖/密钥扫描和构建。新环境应能依据 README 一次启动，健康检查、队列、数据库和对象存储连通后才算初始化完成。
