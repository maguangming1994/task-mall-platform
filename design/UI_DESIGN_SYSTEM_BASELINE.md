# UI 视觉、图标与原型验收基线

## 1. 已确认方向

- 视觉气质：可信、清爽、轻活力，弱化廉价促销感。
- 暂定品牌主色：品牌蓝；奖励、积分和关键收益使用奖励橙点缀；成功、警告、错误使用独立语义色。
- 在品牌名称、Logo 和正式色彩确认前，颜色只通过设计 Token 使用，不把具体色值散落到页面代码。
- 先完成信息架构与低保真流程，再完成关键流程高保真和可点击原型。
- 微信小程序、微信内 H5、微信外 H5 共用视觉系统，管理后台使用更高信息密度的桌面组件。

## 2. 初始设计 Token

| 类型 | 建议 Token | 初始用途 |
|---|---|---|
| 品牌色 | `color-brand-primary` | 主按钮、选中、关键链接；正式色值待品牌资料确认 |
| 奖励色 | `color-reward-accent` | 积分、奖励、收益提示，不代替警告色 |
| 语义色 | `success/warning/danger/info` | 状态表达，必须同时配文字或图标 |
| 间距 | 4px 基础、8px 主节奏 | 组件内外间距不得任意新增 |
| 圆角 | 小/中/大三级 | 输入、卡片、弹窗按组件分级 |
| 字号 | 标题/正文/辅助/数字四类层级 | 金额与积分数字使用统一数字样式 |
| 点击区 | 最小 44×44px | 图标按钮也必须满足 |

正式 V1 Token 已在 `PRODUCT_VISUAL_SYSTEM_V1.md` 和用户端全局样式中生成；后续品牌资料确认时只替换 Token，不逐页散改色值。

## 3. 原型与页面状态

设计顺序：页面地图 → 核心流程 → 低保真 → 任务首页/详情/商品详情视觉样板 → 设计系统 → 全量高保真 → 可点击原型 → 多端走查。

每个页面必须覆盖：

- 默认、加载/骨架、空数据、请求错误与重试。
- 未登录、无权限、被限制、禁用和业务已结束。
- 表单校验、提交中、防重复提交、成功和部分成功。
- 超长文字、极端金额/积分、图片失败和弱网。

## 4. 图标与插画

- 图标采用统一圆角线性风格和 24px 基准网格，常用输出检查 16/20/24/32px。
- 使用 SVG 源文件；小程序 TabBar 另备普通态和选中态资源。
- 禁止把 emoji 当正式业务图标，禁止混用不同描边、透视和圆角体系。
- 图标不能作为关键状态的唯一提示，必须配合文字、颜色或可访问标签。
- 任务、积分、空状态、成功和错误插画使用统一人物比例、光影和色板。
- 每个第三方字体、图标、插画和图片记录来源、授权范围和替换方案。

## 5. 响应式与可访问性

- 用户端优先覆盖小程序常见手机宽度，并验证微信内/外 H5 的安全区、软键盘和返回行为。
- 管理后台覆盖常用桌面分辨率；复杂表格在窄屏横向滚动，不压缩到不可读。
- 正文和辅助文字保持可读对比度；颜色不能是唯一状态提示。
- 表单有明确标签、错误定位和焦点顺序；危险操作提供影响说明而非只写“确定”。
- 动效用于状态反馈，不阻塞主流程，并提供弱性能设备降级。

## 6. 交付物与验收

交付物：页面清单、流程图、低/高保真原型、组件库、Token、图标库、插画/切图、交互说明、多端差异和资源授权表。

页面完成条件：业务和异常路径完整、所有状态齐全、复用已批准组件、资源可直接开发、标注完整，并通过结构、视觉和目标端真机三轮走查。阻断和严重设计问题为零后才能发布。

当前已按中性建议版完成品牌标记、首页高保真结构和五栏导航。仍需业务方在上线前确认正式品牌名称、Logo 与颜色偏好；未提供前继续使用本方案，不阻塞产品化开发。
