# UI、原型与图标设计计划

第二十六组已确认的视觉方向、初始 Token、图标规范、可访问性和交付验收基线见 [`UI_DESIGN_SYSTEM_BASELINE.md`](UI_DESIGN_SYSTEM_BASELINE.md)。品牌资料未提供前使用中性建议版，不阻塞信息架构和低保真原型。

## 1. 设计目标

- 用户能够快速理解“领取任务—提交审核—获得积分—商城兑换”的核心路径。
- 微信小程序、H5、Android 和 iOS 保持统一品牌体验，同时遵守各平台交互习惯。
- 管理后台优先保证信息密度、审核效率和操作安全。
- 所有页面必须覆盖加载、空数据、错误、无权限和操作结果等状态。
- 图标、颜色、字号和间距全部来自设计规范，避免页面各自定义。

## 2. 设计工作流程

### 阶段 D1：需求和信息架构

工作内容：

- 确认用户角色、使用场景和核心目标。
- 整理用户端与管理后台页面清单。
- 绘制任务、积分、商城、订单和支付流程。
- 确认底部导航、页面层级和返回逻辑。
- 标记高风险操作，例如支付、退款、审核驳回和人工扣除积分。

交付物：

- 页面地图
- 用户流程图
- 页面功能清单
- 状态清单

验收门槛：核心流程没有断点，每个入口都有明确出口和异常处理。

### 阶段 D2：低保真原型

工作内容：

- 先完成黑白线框图，不提前纠结颜色和装饰。
- 设计首页、任务、商城、订单、消息和个人中心的页面结构。
- 验证任务领取、成果提交、积分兑换和订单支付的操作步数。
- 设计管理后台的列表、筛选、详情、审核和批量操作。
- 对关键页面制作可交互原型。

交付物放入 `design/prototypes`。

验收门槛：用户端核心任务可以在合理步骤内完成；后台审核人员无需反复跳转即可完成审核。

### 阶段 D3：视觉方向与品牌基础

工作内容：

- 确定品牌关键词和整体视觉气质。
- 设计主色、辅助色、功能色和中性色。
- 设计字体层级、数字样式、圆角、阴影和间距体系。
- 确定插画、图片和图标的统一风格。
- 先用任务首页、任务详情和商品详情制作视觉样板。

验收门槛：三张视觉样板确认后，才批量绘制其余页面。

### 阶段 D4：设计系统和组件库

需要建立的基础规范：

- 颜色 Token
- 字体和字号 Token
- 4/8 倍数间距体系
- 圆角、边框、阴影和遮罩
- 页面安全区和响应式断点
- 图标尺寸、描边和视觉重量

用户端核心组件：

- 按钮、标签、徽标、输入框、选择器
- 任务卡片、商品卡片、积分卡片
- SKU 选择器、数量选择器、价格显示
- 导航栏、标签栏、底部操作栏
- 弹窗、抽屉、Toast、加载和骨架屏
- 空状态、错误状态和权限状态

管理后台核心组件：

- 筛选表单、数据表格、分页器
- 状态标签、详情面板、审核面板
- 批量操作、危险操作确认框
- 商品与 SKU 编辑器
- 数据指标卡和趋势图表
- 配置开关、单选、多选、数字单位输入、时间范围和类目树
- 配置草稿、版本差异、发布确认、审核和回滚面板

交付物放入 `design/design-system`。

### 阶段 D5：图标体系

图标分类：

- 导航图标：首页、任务、商城、消息、我的
- 业务图标：积分、审核、库存、订单、支付、退款、物流
- 操作图标：搜索、筛选、编辑、删除、上传、分享、收藏
- 状态图标：成功、警告、失败、等待、锁定、无权限

制作规则：

- 优先使用 SVG 源文件，保持可缩放和可换色。
- 同一套图标保持统一画布、描边、圆角和视觉重量。
- 同时检查 16、20、24、32 像素下的清晰度。
- 图标不能成为关键信息的唯一表达，必要时配合文字。
- 小程序 TabBar 图标准备普通态和选中态。
- 每个自制或第三方图标记录来源与授权。

图标源文件放入 `design/assets/icons`，开发交付文件放入 `design/exports`。

### 阶段 D6：高保真页面

用户端按以下顺序设计：

1. 登录、隐私授权和账号绑定
2. 首页及任务列表
3. 任务详情、领取和成果提交
4. 审核结果及积分流水
5. 商城首页、分类和商品详情
6. SKU、购物车和确认订单
7. 支付结果、订单和物流
8. 消息、地址、设置和客服

管理后台按以下顺序设计：

1. 登录、布局和权限状态
2. 数据看板
3. 任务列表、编辑、详情和审核
4. 用户、角色和积分流水
5. 商品、SKU 和库存
6. 订单、退款和发货
7. 消息、运营配置和审计日志

每个页面必须设计：

- 默认状态
- 加载与骨架屏
- 空数据状态
- 请求失败及重试
- 禁用和无权限状态
- 表单校验错误
- 成功反馈
- 超长文字、极端数字和图片加载失败

### 阶段 D7：多端适配

- 微信小程序：检查导航、授权弹窗、分包、分享和小程序支付流程。
- 通用 H5：同时检查微信公众号内网页授权、微信内返回和分享，以及微信外浏览器的手机号登录、支付跳转、响应式布局、键盘遮挡和安全区。
- Android/iOS：检查状态栏、底部安全区、返回手势和系统权限。
- 管理后台：重点覆盖常见桌面宽度，表格在窄屏下允许横向滚动。
- 同一业务保持一致，平台专属能力通过 `src/platform` 层接入。

三种购买方式的页面要求：

- 商品详情明确展示该 SKU 支持纯积分、纯现金或现金加积分中的哪些方式。
- 用户选择 SKU 后再选择购买方式，价格随选择实时切换。
- 混合支付统一展示为“¥现金额 + 积分数”，不能只显示折算后的单一价格。
- 积分不足时明确差额，并提供返回做任务或改用其他可用购买方式的入口。
- 确认订单页分别列出商品现金、积分、运费和最终应付金额。
- 支付结果和订单详情分别展示现金支付状态与积分扣除/退回状态。
- 退款页面明确告诉用户现金与积分各自的退回数量和预计到账状态。
- 商品详情只展示后台为当前 SKU 开启的购买方式；切换 SKU 后重新校验可用方式。
- 结算页将商品现金金额、积分、优惠券现金抵扣、优惠券积分抵扣和现金运费分行展示。
- 部分退款页面允许选择数量，并实时展示预计退回的现金、积分、优惠券和运费处理结果。
- 积分明细显示来源、获得时间、剩余数量和过期时间，并提供即将过期提醒。
- 用户中心增加余额入口，余额明细区分任务奖励、消费、退款和人工调整。
- 钱包页面提供余额支付说明、提现申请、提现记录和冻结金额展示。
- 提现确认页实时展示申请金额、手续费率、手续费和预计到账金额。
- 结算页使用支付方式单选：余额支付或微信支付。余额不足以覆盖全部现金应付和运费时禁用余额选项并展示差额；不提供余额金额输入，也不允许余额与微信组合。
- 后台用户详情提供积分、余额和优惠券资产面板；增加、减少、清零均使用带原因和审批提示的操作表单。
- 任务编辑器支持积分、优惠券、余额奖励多选，并显示对应单位和审核提示。
- 提交次数和审核期限支持继承后台默认值或任务单独设置。
- 签到、发帖、评论、完善资料和推荐新人页面显示奖励条件、次数限制和到账状态。
- 发帖页显示标题、正文、图片和视频限制及审核提示；上传区域最多 9 张图片和 1 个视频。
- 社区内容展示审核中、已驳回、已隐藏、申诉中和申诉结果状态。
- 消息中心按任务、资产、订单、售后、社区和系统分类，并支持已读状态。
- 通知设置区分必要消息与营销消息，提供渠道偏好和免打扰时间设置；不可关闭项明确说明原因。
- 举报页面使用后台配置的原因列表，违规处理页展示原因、期限和申诉入口。
- 优惠券选择页只允许选中一张，并明确整单退款返券、部分退款不返券。
- 售后页面先选择售后类型和退货原因，再动态展示预计责任方、原运费处理、退货运费承担及所需凭证。
- 用户选择卖家或物流责任原因时提供图片、视频、物流面单和付款凭证上传入口。
- 最终判责与用户选择不一致时，售后详情展示客服理由和审计记录。
- 商品和订单展示实体物流、无需物流或虚拟交付标识。
- 后台履约操作必须先选择物流发货、无需物流或虚拟交付；仅物流发货显示承运商和单号字段。
- 实体退货页面显示 7 天寄回倒计时；无需物流和虚拟商品不展示物流填写入口。

### 阶段 D8：设计交付和开发走查

设计交付必须包含：

- 页面尺寸、间距、字号和颜色 Token
- 组件各种状态及交互说明
- 图片、图标、占位图和空状态资源
- 页面跳转及弹窗触发条件
- 开发无法从画面判断的业务规则

开发完成后按三轮走查：

1. 结构走查：内容、流程和页面状态是否完整。
2. 视觉走查：字体、间距、颜色、图标和对齐是否一致。
3. 真机走查：小程序、H5、Android 和 iOS 的实际显示及交互。

问题按照阻断、严重、一般、优化四级记录；阻断和严重问题解决后才能发布。

## 3. 与开发计划的配合

| 开发阶段 | 设计需要提前完成 |
|---|---|
| 项目初始化 | 页面地图、设计 Token、导航结构 |
| 登录与权限 | 登录、授权、隐私协议、异常状态 |
| 任务与积分 | 任务全流程、提交表单、审核与积分状态 |
| 商城与订单 | 商品、SKU、购物车、订单和库存提示 |
| 支付与售后 | 支付结果、退款、物流和失败恢复 |
| 发布准备 | 多端走查、资源压缩、适配与无障碍检查 |

设计至少领先开发一个迭代：当前迭代开发时，下一迭代页面应完成评审。

## 4. 每周设计检查清单

- 本周新增页面是否包含全部状态？
- 是否复用了现有组件和图标？
- 是否出现新的颜色、字号或间距值？
- 小程序、H5 和 App 差异是否有明确说明？
- 图片和图标是否已压缩并记录授权？
- 开发实现是否完成设计走查？
- 已发现的问题是否有负责人和完成时间？

## 5. 完成标准

页面只有同时满足以下条件才算完成：

- 原型和业务流程已确认。
- 高保真设计及全部状态已完成。
- 图标和图片资源可直接用于开发。
- 设计 Token 与组件规范一致。
- 多端差异有清晰标注。
- 开发实现通过设计走查和真机检查。
